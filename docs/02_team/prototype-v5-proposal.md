# v5 모험 화면과 실제 API 연결

v5가 서비스 화면이다(2026-10-20 팀 합의로 v4에서 전환). 서비스 주소 `/frontend/`가 v5 HTML을 열고, 기본 모드에서 실제 API를 사용한다. 로그인·건강정보 저장·모델 예측·챌린지 수행·보상 수령·장착·방 꾸미기를 서버에 저장한다. v4 앱 코드는 지웠고, 지우기 전 코드는 커밋 `218dd51`에서 볼 수 있다. 파일 구성과 구현 규칙은 [frontend/README.md](../../frontend/README.md)에 있다.

## 실행

기존 환경변수·MySQL·Valkey·모델 파일·예측 워커를 준비한다. 마이그레이션 `8_20261018093000_v5_adventure.py`와 기존 챌린지·몬스터·보상 시드가 필요하다. 기존 테이블은 삭제하거나 컬럼을 바꾸지 않고 새 테이블 세 개만 추가한다.

API와 같은 출처의 `/frontend/`를 연다. FastAPI의 `/frontend` 정적 제공 경로가 v5 HTML로 넘겨 준다. 프론트 개발 서버를 쓸 경우:

```bash
cd frontend
DANGO_API_ORIGIN=http://127.0.0.1:8001 npm run dev
```

`http://127.0.0.1:5173/frontend/`를 연다. 일반 정적 서버만으로는 실제 API 요청을 처리할 수 없다.

입력 없이 화면만 검토하려면 주소에 `?demo=1`을 붙인다(`/frontend/?demo=1#login`). 이 모드에는 API 미연결 안내가 표시되며 기록은 새로고침하면 초기화된다. 기본 모드는 API 오류를 예시 결과로 대체하지 않는다.

로컬 PHOTO 저장소는 `EVIDENCE_STORAGE_DIR=./media/evidence`처럼 쓰기 가능한 비공개 경로로 지정한다. Docker 기본 경로는 기존 `/app/media/evidence`다. 사진 저장소를 정적 공개 경로에 연결하지 않는다.

## 연결 범위

| 화면 | 실제 연결 |
| --- | --- |
| 회원가입·로그인 | 공통 AuthSession·메모리 토큰·HttpOnly 쿠키 복원. 가입 화면과 중복되는 건강정보는 건강정보 단계에서 모아 가입 요청 |
| 건강정보·예측 | 프로필·진단·복약·간편/정밀 건강정보 저장. 예측 접수와 완료 조회 후 실제 워커 결과로 지도 표시. 실패하면 같은 건강기록(없으면 가장 최근 기록)으로 다시 접수하고, 접수 여부를 모르면 다시 보내지 않는다 |
| 지도·도감 | 서버 위험도·위협도·공략 점수·산정 설명, 직전 대비 위험도 변화(%p). 진단·복약 질환은 확률 대신 진단 관리 중 표시 |
| 전투·오늘의 공략 | 현재 주기 추천·개인 목표·예정 기회 사용. 상세를 본 뒤 시작하거나 '나중에 할게요'·'해당 없어요'로 넘긴다. 제외한 챌린지는 다시 켤 수 있다. 서버 타이머·PHOTO 업로드·수동 확인 제공 |
| 나의 성장 | 경험치·레벨·보상, 건강기록 저장/조회, 월별 인정 수행 도장, 주차별 챌린지 이력 |
| 가방·방 | 서버 뽑기 수령·소유권·장착·가구 배치·재료·단계 복원. 후보 70종은 잠긴 미리보기 유지 |

진행 중에는 공략 대상이 유지된다. 시작 한도·28일 공통 기간·추가 투입·중단 규칙은 기존 API가 판정한다. 비활성 카드나 추천 근거가 없는 요인을 화면에서 임의로 열지 않는다. 식후 걷기는 기존 회당 10분·하루 2회 목표를 사용한다.

## 추가 계약

원본은 사용자가 지정한 [v5 명세 폴더](https://drive.google.com/drive/folders/1noEI1LG28r3cwQCRl-bmka7F0mT3E_hU)의 사본 세 개다. 기존 행·열을 유지하고 테이블·관계·API·요구사항을 뒤에 추가했다.

- `challenge_timer_sessions`: 예정 기회별 서버 시작 시각·목표·만료·완료 기록. 시작 재요청은 기존 세션을 반환한다.
- `reward_draws`: 인정 수행 1건당 카드 다섯 장과 수령 영수증 한 건. 수령 전에는 카드 내용을 응답하지 않는다.
- `adventurer_states`: 소유 장비·가구의 적용 상태, 성장 재료, 아이템 단계.

추가 API는 서버 타이머 시작/조회, 보상 카탈로그, 뽑기 목록/수령, 꾸미기 조회/수정, 단계 상승, 월별 성장 기록의 아홉 개다. 기존 수행 기록에 선택 필드 `timer_session_id`와 응답 `reward_draw_id`를 추가했다. 타이머가 있는 예정 기회는 조회 응답에 세션 식별자를 추가해 새로고침 후 복원한다.

v5는 서버 타이머 세션을 제출한다. 기존 클라이언트의 `value` 방식은 하위 호환을 위해 유지한다. 기존 타이머 API 전체를 서버 세션 필수로 변경한 것은 아니다.

명세 사본은 `scripts/sync_specs.py`로 생성한다. 새 테이블의 ERD·DDL·마이그레이션 SQL은 `scripts/specs/generate_v5_schema.py <테이블명세.xlsx>`로 생성하며 기존 마이그레이션 ORM 상태를 보존한다.

## 통합 보상

예정 기회 인정 완료마다 뽑기 한 번을 생성한다. 목표 초과 수행에는 새 뽑기를 주지 않는다. 뒷면 다섯 장 중 한 장을 고르면 서버가 획득·중복 처리를 한 트랜잭션으로 확정한다(보상 규칙 v2, 2026-10-20). 같은 선택 재요청은 동일 영수증을 반환하고 선택 변경·미소유 장착을 거절한다.

현재 사용 가능한 모자·가방·주사기·수정검·신발, 보상 가구 네 개, 배경 두 개, 장식 두 개와 재료를 사용한다. 기본 가구 네 개와 초록 정원은 무료다. 카드별 RARE 확률은 15%이며 해당 등급 안에서는 동일 확률이다. 성장의 조각 카드는 RARE다. 같은 뽑기 안에서도 중복이 나올 수 있다.

중복 COMMON은 조각 두 개, RARE는 세 개로 전환하고 조각 카드는 두 개를 준다. 단계마다 필요한 조각이 늘어나 2단계는 20개, 3단계는 40개이며 초기 1단계·최대 3단계다. 새 규칙으로 모의실험한 중앙값은 2단계까지 뽑기 18회, 3단계까지 40회다. 기존 첫 식후 걷기 글루코 블레이드 지급과 `/rewards/me` 계약도 유지한다.

성장 아이템은 서버의 `item_stage`에 따라 1단계 새싹의 결정, 2단계 숲의 결정, 3단계 별빛의 결정을 표시한다. 체험 시안과 실제 연결 화면은 같은 단계별 WebP 이미지·이름을 사용한다. 기존 성장의 조각과 같은 보라·파랑 은하빛 보석과 금색 테두리를 유지하며, 단일 결정 → 결정 군집 → 금색 장식이 더해진 결정으로 단계를 구분한다. 단계와 이름은 보조기기에도 함께 전달한다. `growth-shard.webp`는 보유 조각과 재료 카드의 아이콘으로 유지하며 성장 아이템의 단계별 그림과 구별한다.

공략 점수·경험치는 수행 후 갱신하지만 위험도·위협도를 차감하지 않는다. 월요일 KST 초기화와 공략 점수 100점 초과 누적은 기존 서버 규칙을 따른다. 외형 단계는 실천 표현이며 건강 개선이나 봉인 판정을 대신하지 않는다.

## 검증 결과

2026-10-18~20, 기존 서비스와 분리한 MySQL DB·예측 큐·API에서 합성 계정으로 확인했다.

- 실제 서빙 모델 `serving-526040e2c202659d`로 가입 → 건강정보 → 예측 완료 → 지도 → 챌린지 상세 → 시작 확인.
- 실제 서버 타이머를 10분 이상 경과시킨 후 수행 인정, 공략 점수 10점·18 XP·뽑기 저장 확인.
- 현재 활성 추천 마스터에 PHOTO 카드가 없어 검증 DB에만 합성 PHOTO 미션을 만들어 파일 업로드와 수행 기록·보상을 확인했다. 운영 마스터는 변경하지 않았고 사진 내용의 AI 판독은 포함하지 않는다.
- 카드 세 장 수령, 장비 장착, 의자·장식 적용, 새로고침 복원과 월별 수행 도장 확인.
- 백엔드가 직접 제공하는 `/frontend/`로 v5 전환, 폰트·그림 로드, 추천 넘기기·제외·다시 켜기, 재측정 후 직전 대비 표시, 연결이 끊겼을 때 예측 1회 접수를 확인.
- 백엔드 386개 통과·1개 제외, 전체 커버리지 95%. 프론트 단위 14개, 시안 15개, 실제 연결 모드 43개 통과(v4 코드 삭제 후 기준). Ruff 린트·포맷과 NumPy를 포함한 Mypy 검사 통과.

```bash
npm --prefix frontend run test:unit
npm --prefix frontend run test:prototype
npm --prefix frontend run test:v5
DANGO_TEST_SKIP_GRANT=1 UV_NO_SYNC=1 TERM=xterm bash scripts/ci/run_test.sh
```

마지막 명령의 권한 생략 옵션은 테스트 DB 권한이 이미 준비된 환경에서 사용한다. 전체 DB 권한을 넓히지 않고 검증하기 위한 옵션이다. EC2 배포·외부 저장소·운영 DB 마이그레이션은 이번 검증에 포함하지 않는다.

### 성장 결정 이미지 제작

`frontend/docs/prototype/assets/growth-crystal-stage-1.webp`부터 `growth-crystal-stage-3.webp`까지는 내장 이미지 생성 도구로 제작했다. 기존 `growth-shard.webp`를 스타일 참고로 사용하고 원본은 유지했다. 배포 이미지는 투명 배경을 유지한 512px WebP다.

공통 제작 지시: 기존 성장의 조각의 보라·파랑 은하빛, 반투명 보석의 광택과 금색 원형 테두리를 계승한 정면 아이콘. 글자·숫자·워터마크 없이 바깥은 투명하게 표현한다. 단계별 지시: 1단계는 절제된 단일 결정, 2단계는 중앙 결정과 좌우 작은 결정의 군집, 3단계는 풍성한 결정 군집과 금색 왕관·잎 장식으로 진화를 표현한다.

체험 시안은 일반 스크립트를 사용하고 단계별 이미지를 base64로 내장해 `file://…_v5.html?demo=1#rewards`로 직접 열 수 있다. 실제 연결 화면은 공통 모듈을 사용하며, 시안의 단계별 이름과 내장 이미지 바이트가 공통 자산과 일치하는지 자동 검사한다.
