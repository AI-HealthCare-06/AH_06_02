# v5 모험 시안 검토 제안

상태: **팀 의견 수렴 전 제안**. v4 시각 기준이나 기존 API·DB·보상 정책을 대체하는 승인 문서가 아니다. 병합은 작성자가 별도로 판단한다.

## 열어보기

저장소 루트에서 다음 명령으로 정적 웹을 실행한다.

```bash
python -m http.server 8766 --bind 127.0.0.1
```

브라우저에서 [v5 시안](http://127.0.0.1:8766/frontend/docs/prototype/%EB%8B%B9%EA%B3%A0%ED%82%AC%EB%9F%AC-%EB%AA%A8%ED%97%98%EC%8B%9C%EC%95%88_v5.html#login)을 연다. `#risk`로 모험 지도를 바로 볼 수도 있다. 실행 중인 서버와 포트가 겹치면 다른 포트를 지정한다.

모든 화면에 `팀 검토용 v5 · API 미연결 · 예시 데이터`를 표시한다. 입력·수행·획득은 현재 탭의 메모리에만 남고 새로고침하면 초기화된다. 실제 이메일·비밀번호·건강정보를 입력할 필요가 없다. 로그인·가입·예측 대기는 화면 흐름을 보여주는 체험이며 서버 인증·예측·저장을 실행하지 않는다.

실제 서비스는 기존 `frontend/index.html`과 공통 API 연결 화면이다. 이번 제안에서 서비스 진입점이나 라우터를 v5로 전환하지 않는다. 공식 명세 사본과 `design.md`, v4 기준도 변경하지 않는다.

## 검토할 화면

- 공통 흐름: 로그인 → 회원가입 → 기본정보 → 생활습관 → 선택 검진정보 → 예측 예시 → 모험 지도.
- 공략: 지도 → 추천 카드 상세 → 시작 → 오늘의 예정 기회 → 완료 결과 체험 → 공략 점수·XP·기록.
- 보상: 가방의 아이템 후보 70종·보상 체험·보상함·모험가와 방 꾸미기.
- 성장: 캐릭터·건강 데이터·수행 달력·주차별 선택 이력.
- 도감: 위험요인 상태·다섯 단계 외형 미리보기·수행 후 변화.

## 기획과 맞춘 부분

| 항목 | 시안 반영 |
| --- | --- |
| 위험도·위협도·공략 점수 | 별도 표시. 완료 체험으로 위험도·위협도를 낮추지 않음 |
| 대상 | 예시 최고 위협도 비세라 추천. 시작 전 알데 선택 가능, 시작 후 같은 주기 대상 고정 |
| 0점·미산정 | 코티니와 스파이크는 공략 시작 불가, 도감에서 외형 미리보기 가능 |
| 챌린지 한도 | 초기 동시 2개, 시작 7일 경과 후 해당 주기에 추가 1개, 동시 최대 3개. 중단 시 추가 횟수 환급 없음 |
| 기간 | 추가·재시작으로 시작일을 바꾸지 않음. 기존 시작일+27일까지만 공략 가능 |
| 중단·기록 | 중단해도 수행·XP·공략 점수 유지. 같은 주의 선택 이력과 같은 날짜의 건강정보도 덮어쓰지 않음 |

| 진단·복약 | 해당 질환의 예시 확률 대신 `진단 관리 중` 표시 |
| 접근성 | 320px 가로 넘침 방지, 축소 모션·영상 정지, 메뉴·미리보기 키보드 조작 확인 |

## 합의가 필요한 제안

1. **보상 성향별 화면**: 기존 기획은 수집형·성장형·꾸미기형의 성향을 저장하고 이후 화면·보상을 분기하는 방향이다. 제공받은 v5는 공통 가방에서 여러 유형을 함께 체험하는 대안이다. 유형별 구분 여부는 이번 HTML로 확정하지 않는다. 공통 공략 화면을 유지하면서 보상 화면·테마만 나눌지 팀 검토가 필요하다.
2. **보상 체험 규칙**: 5장 중 3장 선택, 희귀도·중복 재료 전환·재료 소비·가구 획득은 제안 예시다. 실제 지급 계약이 아니다. 현재 서비스의 확정 보상은 보상 성향과 관계없이 식후 걷기 첫 인정 완료에 지급하는 공통 글루코 블레이드다.
3. **외형 단계**: 누적 0·5·10·15·20회는 시각 비교용 임시 기준이다. 건강 개선·습관 형성·봉인 판정이 아니다. 기존 28일 누적 진행률 표현과 어떤 기준으로 연결할지 검토해야 한다.
4. **가입 입력 배치**: v5는 진단·복약·프로필을 건강정보 단계에 모아 보여준다. 실제 회원가입 API에서 필요한 진단·복약 응답을 뒤로 미루는 계약 변경은 포함하지 않는다.
5. **검증·저장 연결**: 완료 버튼은 인증 결과 미리보기다. 실제 타이머 경과·PHOTO 업로드·예측·보상·꾸미기 저장은 기존 서비스 계약을 사용하는 후속 구현이 필요하다. 후보 70종은 미리보기이며 모두 장착 가능한 상태가 아니다.

## 자산과 검증

이미지·영상은 전달받은 자산에서 가져왔다. 기존 v4와 동일한 이미지·폰트는 `frontend/d/assets/`를 참조하고, 새 이미지는 무손실 WebP로 변환했다. 방 ZIP·작업용 파일·개인 PC의 원본 경로는 포함하지 않는다. 상세 출처는 [자산 안내](../../frontend/docs/prototype/assets/README.md)를 참조한다.

```bash
npm --prefix frontend ci
npm --prefix frontend run test:prototype
```

시안 검사는 전체 14화면·가입부터 수행과 보상까지의 연결·중단 후 기록 보존·모바일·축소 모션·보상함 오류·대상과 투입 한도·입력 계약·주간 점수를 확인한다. 실제 서비스의 API·DB·모델·운영 배포 통합 검증을 대신하지 않는다.
