# 당고킬러 모바일 건강정보 입력: 폰트·드롭다운 제안

상태: 병주님 확인 전 디자인 제안. 구현·배포·기존 디자인 가이드 변경 없음.
기준: http://localhost:8011/frontend/ 실제 연결 모드, 390 × 844 CSS px.
이미지는 GPT Image 시안이며 정확한 폰트 렌더링·CSS 치수 검증 결과가 아니다. 구현 시 이 문서의 수치가 우선한다.

## 권장 방향

A의 기존 화면 흐름을 유지하고, C의 '동시에 한 목록만 펼침' 동작을 적용한다. 권장 이미지의 개정본은 candidate-a-inline-v2.png다.
두 질문은 각각 독립된 라벨·선택값을 갖는 1열 필드로 둔다.
접힌 상태에서는 선택값을 한눈에 비교하고, 펼치면 목록이 문서 흐름에서 뒤 필드를 밀어낸다.
목록을 겹쳐 띄우거나 중앙 팝업·바텀시트로 전환하지 않는다.
이 선택은 사용성 검증 전 권장안이며 최종 승인이 아니다.

## 타이포그래피

| 용도 | 제안 | 굵기 | 줄높이 |
|---|---|---|---|
| 건강정보 화면 제목 | 28px | 700 | 1.4 |
| 음주 등 섹션 제목 | 20px | 700 | 1.5 |
| 질문 라벨 | 16px | 600 | 1.5 |
| 선택값·선택 항목·버튼 | 16px 이상 | 500\~600 | 1.5 |
| 설명·기준 기간·오류 | 14px | 400\~500 | 1.5\~1.6 |

기본 권장 폰트는 기존 Pretendard를 유지한다. 글꼴 교체만으로 개선됐다고 판단하지 않고 크기·굵기·질문 구조를 함께 조정한다.
건강정보 폼 안의 제목은 Pretendard로 통일하고 Adventure/Black Han Sans는 브랜드·게임 표현에 한정하는 안을 제안한다.
이는 현재 v5 제목 규칙의 예외 제안이므로 병주님 확인 뒤 팀 디자인 문서와 함께 결정해야 한다. 현재 가이드는 수정하지 않았다.
작업 종료 전 확인한 팀 가이드에는 모바일 선택 버튼형(16px·48px)이 명시되어 있다. 인라인 드롭다운으로 바꾸는 제안 역시 기존 선택 버튼 규칙을 교체하는 결정이므로 확인 전 자동 적용하지 않는다.

| 후보 | 역할 | 결정 전 확인 |
|---|---|---|
| Pretendard | A 기본 권장, 기존 자산 유지 | 실제 모바일에서 400·600·700 구별 |
| Noto Sans KR | B 대체 후보 | 긴 한글 문구 줄바꿈·숫자 정렬·파일 용량 |
| SUIT / SUIT Variable | C 대체 후보 | 동일 16px에서 읽기 편한지·자간·줄바꿈 |

동시에 여러 한글 웹폰트를 내려받지 않는다. 선택한 한 가지를 로컬 자산으로 제공하고 버전·라이선스를 고정한다.
대체 폰트가 준비되기 전 스택 예: Pretendard, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif.
서체의 가독성 우열은 아직 실사용자 테스트로 검증하지 않았다.
대체안 Noto Sans KR는 Google Fonts의 ofl/notosanskr 배포본을 후보로 특정한다. 범용 Noto Sans CJK 묶음과 혼용하지 않는다.
기본안은 기존 Pretendard 자산이므로 이번 단계에서 새 폰트를 설치하거나 다운로드하지 않았다. 대체안 채택 시 해당 배포본의 커밋·파일 해시·라이선스·서브셋을 먼저 고정한다.

폰트 출처: [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard), [SUIT 공식 저장소](https://github.com/sun-typeface/SUIT), [Noto Sans KR 공식 배포 경로](https://github.com/google/fonts/tree/main/ofl/notosanskr).
라이선스: [Pretendard](https://github.com/orioncactus/pretendard/blob/main/LICENSE), [SUIT](https://github.com/sun-typeface/SUIT/blob/main/LICENSE), [Noto Sans KR](https://github.com/google/fonts/blob/main/ofl/notosanskr/OFL.txt).

## 치수·시각 상태

- 390px 기준 좌우 여백 20px, 필드 사용 가능 폭 350px. 카드 내부 패딩을 중첩해 폭을 불필요하게 줄이지 않는다.
- 드롭다운 트리거·선택 항목·주요 CTA 최소 높이 52px, 모든 대화형 영역 최소 44 × 44 CSS px.
- 질문 간 간격 24px, 라벨과 트리거 8px, 항목 좌우 패딩 16px, 모서리 12px.
- 모든 목록은 1열. 6개 빈도·5개 음주량을 임의의 새 구간으로 바꾸지 않는다.
- 목록은 트리거 바로 아래 같은 폭, position: static, 별도 그림자·백드롭·portal 없음.
- 한 번에 한 목록만 열고, 다른 트리거를 누르면 기존 목록을 닫는다. 다른 필드로 자동 초점 이동하거나 자동으로 다음 목록을 열지 않는다.
- 본문 #202C47, 설명 #64707A, 선택 배경 #F0ECFE, 선택 글자 #5542B5, CTA #1F2B3A.
- 선택 상태는 체크와 배경을 함께 표시한다. 포커스는 최소 2px의 명확한 외곽선으로 구별한다.
- 기본 경계와 포커스/오류 경계를 구별한다. 상태 인지가 필요한 경계·아이콘은 주변과 3:1 대비를 목표로 검증한다.
- 본문 대비 4.5:1 이상을 목표로 검사한다. 색상 토큰만으로 대비 검사를 통과했다고 간주하지 않는다.
- 목록 확장 시 마지막 항목이 가려지지 않게 본문 스크롤을 허용한다. 중첩된 작은 스크롤 영역은 기본으로 사용하지 않는다.
- CTA는 활동량·식생활·가족력 뒤의 기존 제출 순서를 유지하며 본문 흐름에 둔다. 목록 위에 고정해 겹치지 않는다.

44px은 병주님 요청에 따른 자체 최소 터치 기준이다. [WCAG 2.2 AA 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 예외 조건을 둔 24px 기준이고, [AAA 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)는 44px이다. 이 디자인이 전체 WCAG 준수를 검증했다는 뜻은 아니다.
현재 48px 버튼도 사용자 최소 기준을 충족한다. 52px은 단일 열 선택 시 여유를 늘리려는 제안이며 실증된 개선 수치는 아니다.
6개 빈도 목록의 행 높이만 312px이므로 열린 상태에서 음주량까지 항상 한 화면에 보인다고 약속하지 않는다.
드롭다운은 현재 상시 펼침보다 선택마다 탭이 하나 늘어난다. 장점은 닫힌 두 질문의 비교와 폼 길이 감소이며, 완료 시간·오선택률은 검증 전이다.

## 내용과 값

음주 섹션의 기간 안내는 '최근 4주 기준으로 선택해 주세요.'를 유지한다.
질문 라벨은 '마시는 빈도', '한 번에 마시는 양'이다. 반복되는 보조 질문은 줄이고 필요한 설명만 둔다.

| alcohol_frequency | 표시 문구 |
|---|---|
| 1 | 최근 4주 동안 마시지 않음 |
| 2 | 월 1회 미만 |
| 3 | 월 1회 정도 |
| 4 | 월 2\~4회 |
| 5 | 주 2\~3회 |
| 6 | 주 4회 이상 |

| alcohol_amount | 표시 문구 |
|---|---|
| 1 | 1\~2잔 |
| 2 | 3\~4잔 |
| 3 | 5\~6잔 |
| 4 | 7\~9잔 |
| 5 | 10잔 이상 |

미선택의 초기값은 비어 있어야 한다. 시안의 '월 2\~4회 / 3\~4잔'은 설명용 예시이며 기본 선택값으로 적용하지 않는다.
빈도 1을 고르면 음주량 질문을 숨기고 제출값은 기존 계약대로 0이다.
빈도를 다시 음주 쪽으로 바꾸면 음주량 선택을 명시적으로 요구하고, 예전에 숨긴 값을 사용자 확인 없이 다시 채우지 않는 안을 제안한다.
'10잔 이상'을 정확한 잔 수 10으로 바꾸지 않는다. 최근 4주와 원 설문의 기간 차이라는 기존 한계도 유지한다.

## 상호작용·접근성

권장 구조는 일반 button의 펼침 동작과 네이티브 radio 목록이다.
이 구조는 인라인 드롭다운의 모양을 갖되 선택지는 의미가 있는 단일 선택 그룹으로 전달한다.
ARIA combobox·menu 역할을 겉모양에 맞춰 혼합하지 않는다.

- 트리거: type=button, 질문·현재 값이 포함된 접근 가능한 이름, aria-expanded, aria-controls.
- 펼친 영역: 연결된 fieldset/legend 및 동일 name의 radio 6개 또는 5개. 전체 행 라벨을 누를 수 있게 한다.
- Enter/Space로 열고 닫기. 열 때 현재 선택 항목 또는 첫 항목으로 초점을 이동한다.
- 목록을 열면 확정값을 선택 중 임시값으로 복사한다. radio 방향키는 네이티브 동작으로 임시값만 바꾸며, 아직 음주량 숨김·초기화 같은 의존 동작을 하지 않는다.
- 포인터로 항목을 누르거나 Enter/Space로 확정하면 임시값을 확정값에 반영한 뒤 닫고 트리거로 초점을 돌린다. 목록에서 Tab으로 벗어날 때도 현재 임시값을 확정한다. 미선택이면 값은 계속 비어 있다.
- Escape 또는 같은 트리거로 닫기는 임시값을 버리고 기존 확정값을 유지한다. 이 명시적 임시/확정 구조에서만 '취소' 의미를 부여한다.
- Enter/Space 처리로 폼이 암묵적으로 제출되거나 토글이 두 번 실행되지 않도록 막고, 사용법을 짧은 접근성 설명으로 연결한다.
- 저장·예측 요청은 기존 별도 제출 단계에서만 발생한다. 드롭다운 선택 자체로 서버에 저장하지 않는다.
- 오류는 해당 질문 아래 한국어 문구로 표시하고 aria-describedby로 연결한다. 필수 의미·aria-invalid를 일치시킨다. 닫힌 영역의 required radio/select에 브라우저 기본 검증이 초점을 보내는 구조는 사용하지 않는다.
- 제출 전에 확정값을 검사하고 오류 질문의 트리거로 초점을 옮긴 뒤 선택 영역을 연다. 다른 입력의 검증이나 서버 검증은 유지한다.
- 제출값의 원천은 확정값 하나다. 임시 radio 선택을 서버 필드로 중복 제출하지 않는다. 기존 select를 값 저장용으로 유지하면 접근성 트리에서 제외하고, 숨긴 required 컨트롤의 기본 검증 충돌도 함께 제거한다.
- 한 목록을 닫고 다른 목록을 열 때 대상 트리거의 화면 위치를 보정해 손가락 아래 대상이 갑자기 이동하지 않게 한다. 입력 중인 다른 필드로 포커스를 빼앗지 않는다.
- 200% 텍스트 확대와 320px에서도 줄바꿈·스크롤로 전체 항목을 읽을 수 있게 한다.
- VoiceOver/iOS Safari, TalkBack/Android Chrome에서 실제 터치·초점·선택값 알림을 별도로 확인한다.

이 구조는 [W3C Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)를 펼침 동작의 근거로 삼은 제안이다.
기존 APG [select-only combobox 예시](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)를 그대로 복사한 구현이 아니다.
표준 역할을 적었다는 이유만으로 모바일 보조공학 검증이 끝났다고 보지 않는다.

## 화면 상태별 계약

| 상태 | 표시와 값 처리 |
|---|---|
| 미선택 | 두 트리거는 '선택해 주세요'. 빈도·양 모두 빈 값이며 0으로 채우지 않음 |
| 음주 선택 완료 | 빈도 2\~6, 양 1\~5를 두 트리거에 표시 |
| 비음주 확정 | 빈도 1 확정 시에만 양을 숨기고 0으로 만듦. 보조 문구 '음주량 입력은 생략해요' |
| 음주로 다시 변경 | 양을 미선택으로 되돌리고 다시 요구. 이전 값을 자동 확정하지 않음 |
| 방향키로 비음주를 잠시 지남 | 임시값만 변경. 기존 양을 숨기거나 지우지 않음 |
| 빈도 오류 | '마시는 빈도를 선택해 주세요.'를 해당 필드 아래 표시 |
| 음주량 오류 | 빈도 2\~6인데 양이 비면 '한 번에 마시는 양을 선택해 주세요.' 표시. 0으로 통과시키지 않음 |

미선택은 A 개정 이미지에 반영했다. 오류·비음주 상태는 위 문서 계약으로 정의했으며 동작하는 UI나 실기기 캡처로 구현 완료를 주장하지 않는다.

## 승인 뒤 확인할 항목

1. 현재 로컬 390px·320px 화면에서 빈도·양의 미선택/선택/오류/비음주 상태.
2. 선택지는 모두 16px 이상, 행·트리거는 52px 이상이며 긴 문구가 잘리지 않음.
3. 열린 목록이 다음 필드를 밀어내며 팝업·바텀시트·브라우저 기본 선택창이 발생하지 않음.
4. 빈도 1의 음주량 숨김·0 제출, 재선택 시 상태 처리, 값 코드 1\~6·1\~5 유지.
5. 방향키 임시값·Enter/Space·Tab 확정·Escape 취소·포커스 복귀·오류 알림·모바일 스크린리더.
6. 200% 텍스트 확대·모션 감소·CTA 가림·가로 넘침·폰트 로딩 실패.
7. 생성 시안에서 생략된 흡연·활동량·식생활·가족력 입력의 기존 기능 유지. 활동량은 기존 숫자 입력이며 새로운 범주형 선택지를 만들지 않음.
8. 현재 상시 펼침 안을 1열로 정리한 대조군과 선택 탭 수·완료 시간·오선택·스크롤 부담을 비교.
