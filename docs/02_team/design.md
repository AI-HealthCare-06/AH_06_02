# 당고킬러 Design Guide v1

> 기준 화면: v5 HTML(`frontend/docs/prototype/당고킬러-모험시안_v5.html`). 2026-10-20 서비스 화면을 v4에서 v5로 바꿨다.  
> 목적: 팀원이 각자 화면을 고치더라도 같은 시각 규칙과 UX 언어를 유지하기 위한 공통 기준. HTML과 이 문서가 다르면 HTML이 우선한다.

---

## 1. 기본 원칙

1. 건강정보가 게임 요소보다 우선한다.
2. 위험도(질환 예측 확률), 위협도, 공략 점수는 서로 다른 값으로 명확히 구분한다.
3. 위험을 과도하게 자극적으로 표현하지 않는다.
4. 게임 요소는 접근성을 높이는 보조 수단으로 사용한다.
5. 의료 고지와 안전 안내는 눈에 띄되 공포감을 주지 않는 톤을 사용한다.
6. 동일 의미에는 동일한 색·형태·간격 규칙을 사용한다.

---

## 2. Typography

- 본문 폰트: `Pretendard` (`frontend/docs/prototype/assets/v4-2.woff2`)
- 제목·게임 표현 폰트: `Adventure` = Black Han Sans (`v4-1.ttf`). 화면 제목, 캐릭터 이름, 보상 이름처럼 짧은 글에만 쓴다
- 화면 제목(`h1`): Adventure · 700 / 28px. 한 화면에 하나
- 섹션 제목(`h2`): Adventure · 700 / 18px
- 소제목·카드 제목(`h3`): Adventure · 700 / 15px
- 본문: Regular / 12–14px
- 보조 설명: Regular / 11–12px
- Badge / Pill: Medium / 11px
- 숫자 강조:
  - 주요 확률: Bold / 28px
  - 타이머: Bold / 52px

### 사용 규칙
- 화면 제목은 한 화면에 하나다. 카드 안의 이름(예: `Lv. 1 모험가`)은 화면 제목이 아니라 `h2`·`h3`다.
- 제목 크기·굵기는 위 세 단계만 쓴다. 컴포넌트마다 제목 글자 크기를 따로 지정하지 않는다. 화면 폭이 바뀌어도 같은 크기다.
- 필수·선택 표시는 제목 뒤에 작은 글자로 붙인다(`*필수`는 빨강, `(선택)`은 회색).
- 예외는 아래뿐이다. 늘릴 때는 이 목록과 검사 테스트의 예외 목록을 함께 고친다.

| 예외 | 이유 |
| --- | --- |
| 첫 화면·가입 안내·예측 대기 문구(`.hero-copy` · `.signup-copy` · `.waiting-copy`) | 화면 제목이 아니라 큰 안내 문구다 |
| 레벨 숫자(`.growth-level`) | 숫자 강조다 |
| 작은 아이템 카드 이름(`.reward-tile` · `.draw-result` · `.room-prop`) | 좁은 카드 안에 들어가야 한다 |
| 메뉴 창 제목(`#app-menu`) | 화면이 아니라 메뉴다 |

- 검사: `scripts/frontend/v5-live-browser.test.mjs`의 "모든 화면의 제목은 디자인 규칙의 크기·굵기·글꼴을 따르고 화면 제목은 하나다" 테스트가 390px·1440px에서 모든 화면과 탭의 제목을 재서, 규칙을 벗어나면 실패한다.
- 숫자는 단위를 함께 표시한다.
- `위협도 72`, `공략 점수 40`, `고혈압 위험 31%`처럼 이름을 생략하지 않는다.

## 3. Color

### Base
v5 HTML의 `:root` 토큰을 그대로 쓴다.
- Ink(본문): `#202C47`
- Navy(제목·Primary CTA): `#1F2B3A`
- Muted(보조 설명): `#64707A`
- Border: `#E1E3EE`
- Surface/Card: `#FFFFFF`
- 앱 바깥 배경: 어두운 남색 `#14213D` 위에 모험 세계 그림. 화면 영역은 밝은 Surface

### Semantic
- Primary / CTA: Deep Navy `#1F2B3A`
- Game / Accent: Purple fill `#705EE0` / text `#5542B5` / soft(lilac) `#F0ECFE`
- Reward / RARE: Gold `#E9BD77`, RARE 카드 배경 `#FFF9E9`·테두리 `#D3B462`·글자 `#8B651A`
- Success / Completion: Mint fill `#2E7A57` / text `#235F40` / soft `#E6F7ED`
- Caution / Behavioral factor: Amber fill `#B87826` / text `#7A4A12` / soft `#FBF0D4`
- Elevated risk / Attention: Coral fill `#C7544D` / text(threat) `#9E342F` / soft `#FDE8E3`
- Informational / Prediction: 위험도 숫자 `#5266AD`

### 캐릭터
캐릭터는 비세라·알데·코티니·스파이크 네 마리이며 일러스트(`evolution-sprites.webp`·`v4-3.png`)로 구분한다. 캐릭터별 고유색 토큰은 두지 않는다. 수치·게이지·상태 텍스트에는 semantic color를 사용한다.

### 의미 고정
- Coral: 높은 위협·주의가 필요한 값
- Purple: 공략 점수·게임 진행. 텍스트는 Purple text token `#5542B5`를 사용한다.
- Mint: 완료·안전 확인·성공
- Amber: 의료 고지·생활행동 주의
- Blue: 예측 정보·정보성 상태
- Gold: 보상의 희귀도(RARE)·성장 재료. 건강 상태에는 쓰지 않는다

### 대비 규칙
- Secondary text `#64707A`는 11px 이하 보조 설명에서 장문 사용을 피하고, 핵심 정보에는 Primary text를 사용한다.
- 흰 배경의 본문/핵심 텍스트에는 fill용 색상보다 진한 text token을 사용한다.
- 특히 의료 고지, 예측 수치, 경고·성공 라벨은 text token을 우선한다.
- 색만으로 상태를 전달하지 않고 반드시 텍스트 라벨을 함께 사용한다.

## 4. Spacing & Radius

### Spacing scale
`8 / 12 / 16 / 20 / 24`

권장:
- 같은 그룹 내부: 8–12
- 카드 내부: 14–16
- 카드 간 간격: 14–16
- 화면 좌우 padding: 20
- 주요 섹션 간: 20–24

### Radius
- Button: 12–14px
- Card: 18–22px
- 작은 칸(입력·보상 카드·위험도 칸): 10–14px
- Pill/Badge: full rounded

### 화면 폭
- 휴대폰 390px 기준, 320px에서도 가로로 넘치지 않는다.

---

## 5. Button

### Primary
- Deep navy background
- White text
- Bold 14px
- 높이 약 44–48px
- 주요 진행 CTA에만 사용

예:
- `내 위험요인 보기`
- `약점 공략하러 가기`
- `선택한 2개 시작하기`
- `타이머 시작`

### Secondary
- Neutral light gray background
- Deep navy text

예:
- `이 추천은 나와 맞지 않아요`
- `오늘 기록 보기`

한 화면에서 Primary CTA는 원칙적으로 1개만 둔다.

---

## 6. Card

- Surface: white
- Border: 1px light gray
- Radius: 18px
- Padding: 14–16px
- 카드 내부 정보는 제목 → 핵심 값 → 설명 순서

상태 카드는 semantic background를 사용할 수 있다.
- Success: Mint soft
- Warning: Amber soft
- Prediction: Blue soft
- Game: Purple soft

## 7. 위협도 / 공략 점수

### 현재 위협도
- 내부 척도: 0–100
- 재예측/재측정 시 갱신
- 화면에서는 분모를 표시하지 않는다.
- Coral text token `#9E342F` 중심 표현
- 예: `위협도 72`

### 주간 공략 점수
- 주간 목표: 100
- 월요일 00:00 KST 초기화
- 100 초과 시 계속 누적
- 100 미달 불이익 없음
- Purple text token `#5542B5` 사용
- 퍼센트 기호 사용 금지
- 예: `이번 주 공략 점수 40 / 100`

### 금지
- 위협도와 공략 점수를 동일 막대에 겹쳐 표현하지 않는다.
- `공략 점수 40 → 위협도 -40`처럼 직접 차감 관계로 보이게 하지 않는다.

재측정 시:
`위협도 78 / 공략 40 → 재측정 → 새 위협도 56`
처럼 별도 전환으로 표현한다.

## 8. 질환 예측 화면

v5에서는 모험 지도 위쪽의 위험도 칸과 캐릭터 도감의 기여요인 Top3가 이 역할을 나눠 맡는다.

반드시 포함:
- 질환별 상태
- 미진단 질환의 예측 확률
- 진단 질환의 `진단 관리 중` 상태
- 주요 기여요인
- 직전 대비 변화(같은 모델의 직전 예측이 있을 때만, `직전 대비 +0.3%p`)
- 의료 고지

### 부분 진단자
- 당뇨만 진단: 당뇨는 `진단 관리 중`, 고혈압만 예측
- 고혈압만 진단: 고혈압은 `진단 관리 중`, 당뇨만 예측
- 둘 다 진단: 예측 확률 화면 생략
- 둘 다 미진단: 두 질환 모두 예측

## 9. 챌린지 카드

카드 기본 정보:
- 챌린지 제목
- 난이도
- 인증 방식
- 간단한 추천 이유
- 지급 공략 점수

난이도 Badge:
- `쉬움` (`easy`)
- `보통` (`normal`)
- `도전` (`challenge`)

인증 방식 Badge:
- `MANUAL`
- `PHOTO`
- `TIMER`
- `VALUE`
- `TIME`
- `SYSTEM`

카드 이름은 요인별 공격 이름(걷기 공격·근력 공격 등)을 쓴다. `나중에 할게요`와 `해당 없어요`는 실패나 거절과 다른 개념이므로 시각적으로 중립적으로 표현한다. 슬롯이 다 차 지금 시작할 수 없는 추천은 흐리게 막고 `지금은 추가로 시작할 수 없어요`로 알린다.

## 10. 인증 화면

오늘의 공략 화면 기준:
- 현재 챌린지명
- 오늘 목표
- 이번 주 진행 상황
- 인증 방식
- 완료 시 보상
- Primary CTA

### TIMER
- 남은 시간을 가장 크게 표시
- 중간 종료는 완료로 인정하지 않음

### PHOTO
- AI 판정 없음
- 수행 증빙 업로드
- 비공개 저장
- `evidence_url`만 로그에 연결

## 11. 의료·안전 안내

### 의료 고지
- Amber soft background
- `의료 고지` 라벨
- 진단이 아니라는 사실을 명확히 표시

### 운동 전 안전 확인
- 운동형 챌린지 시작 직전에 표시
- 안전 확인 답변은 저장하지 않음
- `safety_confirmed=true`는 시작 시점 서버 검증용

## 12. 화면별 구현 기준

v5 화면은 14개다. 주소의 화면 이름은 괄호 안과 같다.

### 시작 준비
로그인(`login`) · 회원가입(`signup`) · 건강정보 입력(`health`) · 생활습관 입력(`health2`) · 검진정보(`health3`) · 예측 대기(`waiting`).
입력 오류는 해당 칸에 표시한다. 검진정보는 선택 단계임을 제목에 밝힌다.

### 모험 지도 (`risk`)
핵심: 위험도 칸(확률·직전 대비) / 마을별 캐릭터와 위협도 / 의료 고지. 산정되지 않은 마을은 잠근다.

### 캐릭터 도감 (`monsters`)
핵심: 기여요인 Top3 / 캐릭터 / 현재 위협도 / 이번 주 공략 점수 / 산정 설명 / 봉인 상태.
봉인 관련 API 응답값 `state`, `sealed_at`, `seal_count`를 카드에서 표현한다.

### 전투와 챌린지 (`reco`)
핵심: 위협도(재측정 때 바뀐다는 안내) / 공략 점수 / 진행 중 챌린지 / 추천 카드 / 제외한 챌린지.

### 오늘의 공략 (`today`)
핵심: 챌린지 상세(목표·인증 방법·난이도·하루 XP·안전 안내) / 수행 상태 / 인증 / 중단.

### 나의 성장 (`progress`) · 캐릭터 변화 도감 (`evolution`) · 수행 후 변화 (`evolution-complete`)
핵심: 경험치·레벨 / 월별 수행 도장 / 건강 기록 / 캐릭터 외형 단계. 외형 단계 기준이 정해지기 전에는 미리보기로 표시한다.

### 가방 · 나의 보상 (`rewards`)
핵심: 받을 보상 표시 / 카드 뽑기 / 꾸미기 / 성장의 조각과 아이템 단계. 아래 16절을 따른다.

## 13. 공통 상태 규칙

### Loading
- 비동기 예측은 `queued` / `running` 상태를 구분한다.
- 진행 문구 + spinner/skeleton 등 명확한 대기 표현을 사용한다.
- 폴링 기준: 2초 간격 / 최대 20회.
- 시간 초과 시 동일 작업 상태를 다시 확인할 수 있게 하고 자동 중복 제출하지 않는다.

### Error
- 내부 에러 코드 원문을 사용자에게 그대로 노출하지 않는다.
- 사용자가 해결 가능한 설명 + 재시도 또는 이전 화면 CTA를 함께 제공한다.
- validation / network / failed 상태를 구분하되 화면 톤은 일관되게 유지한다.

### Empty
- 오류가 아니라 정상적인 ‘없음’ 상태를 구분한다.
- 예: 아직 챌린지를 시작하지 않음, 캐릭터 미등장, 기록 없음.
- 설명 + 다음 행동 CTA를 제공한다.

## 14. 구현 시 금지사항

- 화면마다 다른 폰트 사용
- 임의의 primary color 추가
- 위협도/공략 점수를 동일 막대에 겹쳐 표현
- 건강 위험을 게임 보상처럼 과장
- 사진 인증을 AI 분석 결과처럼 표현
- 임의의 medical claim 추가
- 버튼, radius, spacing을 화면마다 다르게 적용

## 16. 보상 표시

- 보상은 실천 보상이다. 건강이 나아졌다는 뜻으로 보이게 하지 않고 `위험도`·`위협도`와 연결하지 않는다.
- 희귀도는 COMMON과 RARE 두 가지다. RARE는 Gold 계열 배경·테두리와 `RARE` 글자를 함께 쓴다(색만으로 구분하지 않는다).
- 성장의 조각은 보라 결정에 금빛 테두리를 두른 그림으로 표시하고, 가방 숫자 옆에서는 작은 크기로 쓴다.
- 수행을 놓쳤다고 보상이나 조각을 빼앗지 않는다.
