# 당고킬러 Design Guide v1

> 기준 화면: v5 HTML(`frontend/docs/prototype/당고킬러-모험시안_v5.html`). 2026-10-20 서비스 화면을 v4에서 v5로 바꿨다.  
> 목적: 팀원이 각자 화면을 고치더라도 같은 시각 규칙과 UX 언어를 유지하기 위한 공통 기준. HTML과 이 문서가 다르면 HTML이 우선한다.

---

## 1. 기본 원칙

1. 건강정보가 게임 요소보다 우선한다.
2. 위험도(질환 예측 확률), 위협도, 공략 점수는 서로 다른 값으로 명확히 구분한다.
3. 위험을 과도하게 자극적으로 표현하지 않는다.
4. 게임 요소는 접근성을 높이는 보조 수단으로 사용한다.
5. 의료 고지와 안전 안내는 눈에 띄되 공포감을 주지 않는 톤을 사용한다.
6. 동일 의미에는 동일한 색·형태·간격 규칙을 사용한다.

## 2. Typography

- 본문 폰트: `Pretendard` (`frontend/docs/prototype/assets/v4-2.woff2`)
- 제목·게임 표현 폰트: `Adventure` = Black Han Sans (`v4-1.ttf`). 화면 제목, 캐릭터 이름, 보상 이름처럼 짧은 글에만 쓴다
- 화면 제목(`h1`): Adventure · 700 / 28px. 한 화면에 하나
- 섹션 제목(`h2`): Adventure · 700 / 18px
- 소제목·카드 제목(`h3`): Adventure · 700 / 15px
- 모바일(760px 이하) 굵기: 제목도 Pretendard 700 으로 쓴다(Black Han Sans 는 더 가는 굵기가 없고 실제 폰에서 뭉개진다). Adventure 는 로고(DangoKiller · 당고킬러)에만 남긴다. 숫자·배지 900·800 → 700, 버튼·탭·링크·상단 제목 750 → 600, 본문 속 굵은 이름·라벨 700 → 600. 데스크톱은 위 Adventure 제목 규칙을 그대로 쓴다
- 본문: Regular / 12–14px
- 보조 설명: Regular / 11–12px
- Badge / Pill: Medium / 11px
- 입력·선택 칸(`input` · `select` · `textarea`)의 글자: 16px. 본문 규칙의 예외다. iOS Safari는 16px보다 작은 칸에 초점이 가면 화면을 확대한다. 선택 칸 높이는 44px 이상
- 메뉴 창(`#app-menu`) 항목: 14px, 구분 제목: 12px
- 모바일(760px 이하·높이 610px 이하) 최소 크기: 본문·설명 문구·라벨·버튼·카드 안 챌린지 이름 14px, 보조 표시·배지·지도 위 이름표·전투 화면 점수판 12px. 좁은 칸이라도 이보다 줄이지 않는다
- 글꼴 대체 순서: `Pretendard, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`. 웹폰트가 늦거나 실패해도 한글을 시스템 글꼴로 읽게 한다. 대체 후보(Noto Sans KR · SUIT)는 실제 모바일 비교 전까지 바꾸지 않고, 바꿀 때는 한 가지만 로컬 자산으로 두고 버전·라이선스를 고정한다
- 모바일 건강정보 입력 화면(`.health` · `.health2` · `.health3`) 제목: 화면 제목 Pretendard 700 / 28px · 줄높이 1.4, 섹션 제목만 20px · 줄높이 1.5(다른 화면은 18px). 입력 문항과 같은 글꼴로 읽어 내려가게 하려는 것이다. 설명·기준 기간·오류 문구는 14px · 줄높이 1.5, 좌우 여백 20px. 글자 대비는 실제 배경 기준 4.5:1 이상이라 밝은 회색 배경 위 설명·비활성 단계 이름은 `#64707A`, '*필수'는 불투명 `#C52E3D` 를 쓴다. 다음·예측 보기 같은 주요 버튼은 52px 이상
- 모바일 선택 입력(진단·복약·음주·외식): 브라우저 선택 창 대신 **펼침 목록**으로 받는다. 근거 스펙: [`mobile-design-20261030/font-dropdown-spec.md`](mobile-design-20261030/font-dropdown-spec.md)(아스트라 최종안, 병주님 확정). 선택 창 목록은 기기마다 다르게 뜨고(아이폰 아래쪽 휠, 안드로이드 가운데 창) 페이지 글자 크기를 따르지 않기 때문이다. 데스크톱은 select 를 그대로 쓴다
  - 구조: 질문 라벨(16px · 600) 아래 8px 에 트리거 버튼, 누르면 같은 폭의 1열 라디오 목록이 트리거 바로 아래 문서 흐름에 펼쳐져 뒤 필드를 밀어낸다. 팝업·바텀시트·그림자·겹쳐 띄우기 없음. 질문 사이 간격 24px
  - 치수: 트리거·행 높이 52px 이상, 글자 16px(선택값 500, 고른 행 600), 좌우 패딩 16px, 모서리 12px. 모든 대화형 영역 44 × 44px 이상
  - 색: 본문 `#202C47`, 설명·미선택 문구 `#64707A`, 고른 행 배경 `#F0ECFE` · 글자 `#5542B5` + 체크 표시, 트리거 기본 경계 `#848B9F`, 펼침·초점 경계 `#5542B5`(초점 외곽선 2px), 오류 경계 `#9E342F` 2px
  - 동작: 한 번에 한 목록만 연다. 다른 트리거를 누르면 앞 목록은 닫히고(고르던 값은 버림), 새로 여는 트리거가 손가락 아래에서 움직이지 않게 스크롤을 보정한다. 다음 목록을 자동으로 열거나 초점을 옮기지 않는다
  - 임시값·확정값: 열린 동안 라디오 값은 임시값이다. 행을 누르거나 Enter · Space 로 고르면 확정하고 닫은 뒤 트리거로 초점을 돌린다. Tab 으로 벗어나도 확정, 목록 밖을 눌러도 확정하고 닫는다. Esc 나 같은 트리거로 닫으면 버린다. 방향키는 임시값만 바꿔 '마시지 않음'을 지나가도 음주량을 숨기거나 지우지 않는다. Enter 로 폼이 제출되지 않는다
  - 미선택은 '선택해 주세요'(빈 값, 0 으로 채우지 않음). 빈도 '최근 4주 동안 마시지 않음' 확정 시에만 음주량을 숨기고 0 으로 보내며 빈도 아래 '음주량 입력은 생략해요.'를 보인다. 다시 음주로 바꾸면 음주량은 미선택으로 돌아가 다시 고르게 한다. 음주량 아래에는 '한 번 마실 때 마시는 잔 수예요.'
  - 오류: '○○을 선택해 주세요.'를 그 질문 아래 14px 로 보이고 트리거에 `aria-invalid` · `aria-describedby` 를 단다. 제출할 때 오류가 나면 그 트리거로 초점을 옮기고 목록을 연다
  - 접근성: 트리거는 `button` + `aria-expanded` · `aria-controls`, 이름은 질문과 현재 값. 목록은 `fieldset` + `legend` + 같은 `name` 의 라디오(행 전체가 라벨). combobox · menu 역할을 섞지 않는다(W3C Disclosure 패턴)
- 숫자 강조:
  - 주요 확률: Bold / 28px
  - 타이머: Bold / 52px

### 사용 규칙
- 화면 제목은 한 화면에 하나다. 카드 안의 이름(예: `Lv. 1 모험가`)은 화면 제목이 아니라 `h2`·`h3`다.
- 제목 크기·굵기는 위 세 단계만 쓴다. 컴포넌트마다 제목 글자 크기를 따로 지정하지 않는다. 화면 폭이 바뀌어도 같은 크기다.
- 필수·선택 표시는 제목 뒤에 작은 글자로 붙인다(`*필수`는 빨강, `(선택)`은 회색).
- 예외는 아래뿐이다. 늘릴 때는 이 목록과 검사 테스트의 예외 목록을 함께 고친다.

| 예외 | 이유 |
| --- | --- |
| 첫 화면·가입 안내·예측 대기 문구(`.hero-copy` · `.signup-copy` · `.waiting-copy`) | 화면 제목이 아니라 큰 안내 문구다 |
| 레벨 숫자(`.growth-level`) | 숫자 강조다 |
| 작은 아이템 카드 이름(`.reward-tile` · `.draw-result` · `.room-prop`) | 좁은 카드 안에 들어가야 한다 |
| 메뉴 창 제목(`#app-menu`) | 화면이 아니라 메뉴다 |

- 검사: `scripts/frontend/v5-live-browser.test.mjs`의 "모든 화면의 제목은 디자인 규칙의 크기·굵기·글꼴을 따르고 화면 제목은 하나다" 테스트가 390px·1440px에서 모든 화면과 탭의 제목을 재서, 규칙을 벗어나면 실패한다.
- 숫자는 단위를 함께 표시한다.
- `위협도 72`, `공략 점수 40`, `고혈압 위험 31%`처럼 이름을 생략하지 않는다.

## 3. Color

### Base
v5 HTML의 `:root` 토큰을 그대로 쓴다.
- Ink(본문): `#202C47`
- Navy(제목·Primary CTA): `#1F2B3A`
- Muted(보조 설명): `#64707A`
- Border: `#E1E3EE`
- Surface/Card: `#FFFFFF`
- 앱 바깥 배경: 어두운 남색 `#14213D` 위에 모험 세계 그림. 화면 영역은 밝은 Surface

### Semantic
- Primary / CTA: Deep Navy `#1F2B3A`
- Game / Accent: Purple fill `#705EE0` / text `#5542B5` / soft(lilac) `#F0ECFE`
- Reward / RARE: Gold `#E9BD77`, RARE 카드 배경 `#FFF9E9`·테두리 `#D3B462`·글자 `#8B651A`
- Success / Completion: Mint fill `#2E7A57` / text `#235F40` / soft `#E6F7ED`
- Caution / Behavioral factor: Amber fill `#B87826` / text `#7A4A12` / soft `#FBF0D4`
- Elevated risk / Attention: Coral fill `#C7544D` / text(threat) `#9E342F` / soft `#FDE8E3`
- Informational / Prediction: 위험도 숫자 `#5266AD`

### 캐릭터
캐릭터는 비세라·알데·코티니·스파이크 네 마리이며 일러스트(`evolution-sprites.webp`·`v4-3.png`)로 구분한다. 캐릭터별 고유색 토큰은 두지 않는다. 수치·게이지·상태 텍스트에는 semantic color를 사용한다.

### 의미 고정
- Coral: 높은 위협·주의가 필요한 값
- Purple: 공략 점수·게임 진행. 텍스트는 Purple text token `#5542B5`를 사용한다.
- Mint: 완료·안전 확인·성공
- Amber: 의료 고지·생활행동 주의
- Blue: 예측 정보·정보성 상태
- Gold: 보상의 희귀도(RARE)·성장 재료. 건강 상태에는 쓰지 않는다

### 대비 규칙
- Secondary text `#64707A`는 11px 이하 보조 설명에서 장문 사용을 피하고, 핵심 정보에는 Primary text를 사용한다.
- 흰 배경의 본문/핵심 텍스트에는 fill용 색상보다 진한 text token을 사용한다.
- 특히 의료 고지, 예측 수치, 경고·성공 라벨은 text token을 우선한다.
- 색만으로 상태를 전달하지 않고 반드시 텍스트 라벨을 함께 사용한다.

## 4. Spacing & Radius

### Spacing scale
`8 / 12 / 16 / 20 / 24`

권장:
- 같은 그룹 내부: 8–12
- 카드 내부: 14–16
- 카드 간 간격: 14–16
- 화면 좌우 padding: 20
- 주요 섹션 간: 20–24

### Radius
- Button: 12–14px
- Card: 18–22px
- 작은 칸(입력·보상 카드·위험도 칸): 10–14px
- Pill/Badge: full rounded

### 화면 폭
- 휴대폰 390px 기준, 320px에서도 가로로 넘치지 않는다.

## 5. Button

### Primary
- Deep navy background
- White text
- Bold 14px
- 높이 약 44–48px
- 주요 진행 CTA에만 사용

예:
- `내 위험요인 보기`
- `약점 공략하러 가기`
- `선택한 2개 시작하기`
- `타이머 시작`

### Secondary
- Neutral light gray background
- Deep navy text

예:
- `이 추천은 나와 맞지 않아요`
- `오늘 기록 보기`

한 화면에서 Primary CTA는 원칙적으로 1개만 둔다.

## 6. Card

- Surface: white
- Border: 1px light gray
- Radius: 18px
- Padding: 14–16px
- 카드 내부 정보는 제목 → 핵심 값 → 설명 순서

상태 카드는 semantic background를 사용할 수 있다.
- Success: Mint soft
- Warning: Amber soft
- Prediction: Blue soft
- Game: Purple soft

## 7. 위협도 / 공략 점수

### 현재 위협도
- 내부 척도: 0–100
- 재예측/재측정 시 갱신
- 화면에서는 분모를 표시하지 않는다.
- Coral text token `#9E342F` 중심 표현
- 예: `위협도 72`

### 주간 공략 점수
- 주간 목표: 100
- 월요일 00:00 KST 초기화
- 100 초과 시 계속 누적
- 100 미달 불이익 없음
- Purple text token `#5542B5` 사용
- 퍼센트 기호 사용 금지
- 예: `이번 주 공략 점수 40 / 100`

### 금지
- 위협도와 공략 점수를 동일 막대에 겹쳐 표현하지 않는다.
- `공략 점수 40 → 위협도 -40`처럼 직접 차감 관계로 보이게 하지 않는다.

재측정 시:
`위협도 78 / 공략 40 → 재측정 → 새 위협도 56`
처럼 별도 전환으로 표현한다.

## 8. 질환 예측 화면

v5에서는 모험 지도 위쪽의 위험도 칸과 캐릭터 도감의 기여요인 Top3가 이 역할을 나눠 맡는다.

반드시 포함:
- 질환별 상태
- 미진단 질환의 예측 확률
- 진단 질환의 `진단 관리 중` 상태
- 주요 기여요인
- 직전 대비 변화(같은 모델의 직전 예측이 있을 때만, `직전 대비 +0.3%p`)
- 의료 고지

### 부분 진단자
- 당뇨만 진단: 당뇨는 `진단 관리 중`, 고혈압만 예측
- 고혈압만 진단: 고혈압은 `진단 관리 중`, 당뇨만 예측
- 둘 다 진단: 예측 확률 화면 생략
- 둘 다 미진단: 두 질환 모두 예측

## 9. 챌린지 카드

카드 기본 정보:
- 챌린지 제목
- 난이도
- 인증 방식
- 간단한 추천 이유
- 지급 공략 점수

난이도 Badge:
- `쉬움` (`easy`)
- `보통` (`normal`)
- `도전` (`challenge`)

인증 방식 Badge:
- `MANUAL`
- `PHOTO`
- `TIMER`
- `VALUE`
- `TIME`
- `SYSTEM`

카드 이름은 요인별 공격 이름(걷기 공격·근력 공격 등)을 쓴다. `나중에 할게요`와 `해당 없어요`는 실패나 거절과 다른 개념이므로 시각적으로 중립적으로 표현한다. 슬롯이 다 차 지금 시작할 수 없는 추천은 흐리게 막고 `지금은 추가로 시작할 수 없어요`로 알린다.

## 10. 인증 화면

오늘의 공략 화면 기준:
- 현재 챌린지명
- 오늘 목표
- 이번 주 진행 상황
- 인증 방식
- 완료 시 보상
- Primary CTA

### TIMER
- 남은 시간을 가장 크게 표시
- 중간 종료는 완료로 인정하지 않음

### PHOTO
- AI 판정 없음
- 수행 증빙 업로드
- 비공개 저장
- `evidence_url`만 로그에 연결

## 12. 화면별 구현 기준

v5 화면은 14개다. 주소의 화면 이름은 괄호 안과 같다.

### 시작 준비
로그인(`login`) · 회원가입(`signup`) · 건강정보 입력(`health`) · 생활습관 입력(`health2`) · 검진정보(`health3`) · 예측 대기(`waiting`).
입력 오류는 해당 칸에 표시한다. 검진정보는 선택 단계임을 제목에 밝힌다.
로그인·가입 배경은 영상 한 겹이다. 영상 안에 캐릭터가 있으므로 영상이 실제로 재생되는 동안 대체 그림(스프라이트·탐험가)은 숨기고, 자동 재생이 막히거나 모션 줄이기일 때만 대체 그림을 보인다. 문구 뒤는 밝은 막(위쪽 46%까지 불투명도 약 0.9)으로 받친다.

### 모험 지도 (`risk`)
핵심: 위험도 칸(확률·직전 대비) / 마을별 캐릭터와 위협도 / 의료 고지. 산정되지 않은 마을은 잠근다.

### 캐릭터 도감 (`monsters`)
핵심: 기여요인 Top3 / 캐릭터 / 현재 위협도 / 이번 주 공략 점수 / 산정 설명 / 봉인 상태.
봉인 관련 API 응답값 `state`, `sealed_at`, `seal_count`를 카드에서 표현한다.

### 전투와 챌린지 (`reco`)
핵심: 위협도(재측정 때 바뀐다는 안내) / 공략 점수 / 진행 중 챌린지 / 추천 카드 / 제외한 챌린지.
모바일: 카드는 아래 한 줄 가로 띠(카드 폭 42%, 높이 76px, 옆으로 넘김)로 두고, 그 위 남은 높이에 모험가(왼쪽)와 캐릭터(오른쪽)를 같은 바닥선에 나란히 세운다. 둘 다 잘리지 않게 높이에 맞춰 줄인다. 카드 글은 공격 이름(13px)·챌린지 이름(14px)·잠금 안내(12px) 모두 한 줄이고 넘치면 말줄임, 공격 이름도 Pretendard 다. 안내 문구는 카드 띠 바로 위에 둔다.

### 오늘의 공략 (`today`)
핵심: 챌린지 상세(목표·인증 방법·난이도·하루 XP·안전 안내) / 수행 상태 / 인증 / 중단.

### 나의 성장 (`progress`) · 캐릭터 변화 도감 (`evolution`) · 수행 후 변화 (`evolution-complete`)
핵심: 경험치·레벨 / 월별 수행 도장 / 건강 기록 / 캐릭터 외형 단계. 외형 단계 기준이 정해지기 전에는 미리보기로 표시한다.

모바일 히스토리: 캐릭터 그림은 70 × 86px 로 왼쪽 열 안에만 두고 글 열과 겹치지 않는다.

### 하단 메뉴 (모바일)
늘 보이는 아래 띠다. 높이 60px(+기기 아래 안전 여백), 좌우 8px 띄우고 1px 테두리 `#D6D9E8` · 모서리 16px · 옅은 그림자로 떠 있는 띠처럼 둔다. 항목은 높이 44px · 아이콘 18px · 글자 12px 600, 지금 화면 항목은 `#F0ECFE` 배경 + `#C9BFF5` 테두리 + `#5542B5` 글자. 데스크톱은 기존 옆 메뉴를 그대로 쓴다.

### 가방 · 나의 보상 (`rewards`)
핵심: 받을 보상 표시 / 카드 뽑기 / 꾸미기 / 성장의 조각과 아이템 단계. 아래 16절을 따른다.

## 13. 공통 상태 규칙

### Loading
- 비동기 예측은 `queued` / `running` 상태를 구분한다.
- 진행 문구 + spinner/skeleton 등 명확한 대기 표현을 사용한다.
- 폴링 기준: 2초 간격 / 최대 20회.
- 시간 초과 시 동일 작업 상태를 다시 확인할 수 있게 하고 자동 중복 제출하지 않는다.

### Error
- 내부 에러 코드 원문을 사용자에게 그대로 노출하지 않는다.
- 사용자가 해결 가능한 설명 + 재시도 또는 이전 화면 CTA를 함께 제공한다.
- validation / network / failed 상태를 구분하되 화면 톤은 일관되게 유지한다.

### Empty
- 오류가 아니라 정상적인 ‘없음’ 상태를 구분한다.
- 예: 아직 챌린지를 시작하지 않음, 캐릭터 미등장, 기록 없음.
- 설명 + 다음 행동 CTA를 제공한다.

## 16. 보상 표시

- 보상은 실천 보상이다. 건강이 나아졌다는 뜻으로 보이게 하지 않고 `위험도`·`위협도`와 연결하지 않는다.
- 희귀도는 COMMON과 RARE 두 가지다. RARE는 Gold 계열 배경·테두리와 `RARE` 글자를 함께 쓴다(색만으로 구분하지 않는다).
- 성장의 조각은 보라 결정에 금빛 테두리를 두른 그림으로 표시하고, 가방 숫자 옆에서는 작은 크기로 쓴다.
- 수행을 놓쳤다고 보상이나 조각을 빼앗지 않는다.

## 17. 질의 챗봇 화면 (초안)

> 상태: 초안(2026-10-28). API(`/challenge-chat` · `/challenge-chat/select`)만 있고 v5 HTML에는 화면이 없다. 화면을 만들 때 이 절을 따르고, HTML이 생기면 HTML을 기준으로 이 절을 고친다.

챗봇은 챌린지를 **고르는 것을 돕는 대화**다. 건강 상담이 아니다. 대화로 정보를 모으고, 고른 결과는 기존 챌린지 카드로 보여 준다. 새 색·새 글꼴·새 카드 모양을 만들지 않는다.

### 화면 구성 (휴대폰 390px 기준)

위에서 아래로: 상단바(뒤로·`공략 도우미`) → 대화 목록(스크롤) → 의료 안내 한 줄 → 주 버튼 `이 대화로 챌린지 고르기` → 입력창.

- 대화 화면에서는 하단 탭 바를 숨긴다. 입력창이 화면 맨 아래에 붙는다.
- 화면 제목(`h1`)은 `공략 도우미` 하나다. 고른 결과 묶음 제목은 `h2`(`대화로 고른 챌린지`)다.
- 320px에서도 가로로 넘치지 않는다. 말풍선은 줄바꿈하고 카드는 한 줄에 하나다.

### 말풍선

| 구분 | 위치 | 배경 | 글자 | 모서리 |
| --- | --- | --- | --- | --- |
| AI(공략 도우미) | 왼쪽, 최대 폭 85% | Surface `#FFFFFF` + Border 1px `#E1E3EE` | Ink `#202C47` | 18px, 왼쪽 위만 6px |
| 사용자 | 오른쪽, 최대 폭 80% | Purple soft `#F0ECFE` | Ink `#202C47` | 18px, 오른쪽 위만 6px |
| 고정 안내(꺼짐·오류) | 왼쪽 | Surface + Border | Muted `#64707A` | AI와 같음 |
| 건강 판단 거절 안내 | 왼쪽 | Amber soft `#FBF0D4` | Amber text `#7A4A12` | AI와 같음 |

- 사용자와 AI는 색만이 아니라 **위치(왼쪽·오른쪽)와 라벨**로도 구분한다. AI 말풍선 묶음 위에 `공략 도우미` 라벨(11px Medium, Muted)을 붙이고, 사용자 말풍선에는 화면 읽기용 `나:`만 둔다.
- Deep Navy는 주 버튼에만 쓴다. 말풍선에 쓰면 한 화면에 Primary가 여러 개처럼 보인다.
- 같은 사람의 말풍선 사이는 6px, 말한 사람이 바뀌면 14px를 띄운다.
- 서버가 돌려준 고정 문장(`off` · 오류 · 건강 판단 거절)은 그대로 보여 준다. 오류는 Coral로 칠하지 않는다. 사용자의 잘못이 아니다.

### 타이포그래피

- 말풍선 본문: Pretendard Regular **14px**, 줄 간격 1.6. 2절 본문 규칙(12–14px)의 위쪽 값을 쓴다. 대화는 읽는 글이라 12px를 쓰지 않는다.
- 말풍선 안에서는 Adventure 글꼴과 굵게·색 강조를 쓰지 않는다. AI 문장이 진단이나 보장처럼 보이지 않게 한다.
- 라벨·안내: 11–12px. 의료 안내 한 줄은 12px Amber text.
- 입력창 글자: **16px**. 본문 규칙의 예외다. iOS Safari는 16px보다 작은 입력칸에 초점이 가면 화면을 확대한다.
- 숫자는 단위와 함께 쓴다(`10분`). AI 문장 속 목표 숫자는 서버가 서빙 값과 같은지 검사한다.

### 챌린지 카드와의 연결

`/challenge-chat/select` 결과는 **전투 화면(`reco`)의 추천 카드와 같은 카드**로 그린다. 응답 항목은 CHLG-02 카드와 같은 필드(`title` · `description` · `difficulty` · `verification_type` · 목표 값 · `safety_check_required` · `context_type` 등)를 가진다.

| `mode` | 보여 줄 것 |
| --- | --- |
| `conversation` | AI 말풍선에 `answer` 한 줄 → 그 아래(말풍선 밖)에 `h2` `대화로 고른 챌린지` + 카드 1\~3장. 카드마다 `고른 이유` 라벨(11px Muted)과 `reason`(13px Ink) 한 줄을 9절 카드 기본 정보 아래에 붙인다 |
| `ask` | AI 말풍선 안에 `questions`의 선택지를 칩 버튼(높이 44px, Secondary)으로 보여 준다. 자유 입력으로 답받지 않는다 |
| `rules` | 같은 카드에 `h2` `추천 챌린지`를 쓰고, 위에 `지금은 대화로 고르지 못해 추천 목록을 보여 드려요.`(12px Muted)를 둔다. 이유 줄은 없다 |
| `hold` | 13절 Empty 상태. 설명 + `모험 지도로 가기` |

- 카드를 누르면 전투 화면과 **같은 상세·시작 흐름**을 쓴다. 운동 전 안전 확인(11절), 이벤트형 챌린지의 예정 이용일을 거쳐 CHLG-05(`recommendation_ids`)로 시작하고 `오늘의 공략`으로 간다.
- 근거 카드 ID(`evidence_card_ids`)와 출처(`sources`)는 사용자에게 보여 주지 않는다. 운영 기록용이다.
- 시작하려고 전투 화면으로 보내지 않는다. 전투 화면은 열 때마다 규칙 추천을 새로 만들어(CHLG-01) 같은 챌린지의 대화 추천을 가리고, `고른 이유`는 CHLG-02에 없다. 보내야 하면 새로 만들지 않는 경로(`keepRecommendations`)로 연다.
- 슬롯이 다 찬 카드는 9절처럼 흐리게 막고 `지금은 추가로 시작할 수 없어요`로 알린다.

### 버튼과 입력창

- 주 버튼 `이 대화로 챌린지 고르기`(Primary, 높이 48px)는 AI 답이 한 번 온 뒤부터 보인다. 결과 카드가 나오면 숨기고, 카드의 시작 버튼이 그 화면의 Primary가 된다.
- 입력창: 1\~4줄까지 자라는 `textarea`, 최소 높이 44px, 모서리 14px, Border `#E1E3EE`. 안내 문구는 `하루 일과를 편하게 적어 주세요. 이름·연락처는 적지 말아 주세요.`
- 보내기 버튼: 44×44px 아이콘 버튼, Purple text `#5542B5` on Purple soft. 비어 있거나 답을 기다리는 동안은 비활성.
- 글자 수는 메시지당 400자. 350자부터 `350 / 400`을 12px로 보인다. 대화는 12개까지이고, 다 차면 `대화가 길어졌어요. 지금까지 내용으로 골라 볼까요?`와 주 버튼만 남긴다.
- 입력창 아래에 `env(safe-area-inset-bottom)`만큼 여백을 둔다. 키보드가 올라와도 입력창과 마지막 말풍선이 가려지지 않게 `100dvh` 기준으로 배치한다.

### 상태

- 답을 기다릴 때: AI 자리에 `답을 만들고 있어요` 말풍선과 점 3개. `prefers-reduced-motion`이면 점을 움직이지 않는다.
- 꺼짐(`mode: off`): 서버 안내 말풍선을 보이고 입력창을 비활성으로 둔 채 `추천 목록 보기`(Secondary) 버튼을 준다.
- 실패한 요청은 자동으로 다시 보내지 않는다. 오류 말풍선 아래 `다시 보내기`(Secondary)를 둔다.

### 개인정보·안전

- 대화 기록은 메모리에만 둔다. localStorage·sessionStorage에 저장하지 않는다(프론트 AGENTS 규칙). 새로고침하면 대화가 사라진다는 것을 첫 안내 말풍선에 적는다.
- 의료 안내 한 줄(`건강 수치·질환 판단은 하지 않아요. 진단·치료는 의료진과 상의해 주세요.`)을 입력창 위에 늘 둔다.
- AI 답 옆에 `위험도`·`위협도`·예측 확률을 함께 보여 주지 않는다. 대화와 건강 수치가 이어진 것처럼 읽힌다.

### 접근성

- 대화 목록은 `role="log"` + `aria-live="polite"`로 새 말풍선을 읽게 한다.
- 칩·버튼·입력창은 키보드로 닿고 초점 테두리가 보인다. 말풍선 글자 대비는 4.5:1 이상이다(위 표의 색은 모두 넘는다).
