# 당고킬러 Design Guide v2

> 확정: 2026-10-30(병주님). 기준은 실제 화면, 곧 v5 HTML(`frontend/docs/prototype/당고킬러-모험시안_v5.html`)과 그 위에 덮는 `frontend/v5/live.css` · `frontend/v5/app.mjs`다.
> 이 문서는 그 화면의 규칙을 적는다. 규칙을 바꿀 때는 화면 코드·이 문서·검사 테스트를 한 PR에서 같이 고친다.
> 근거 자료: 모바일 선택 입력 스펙 [`mobile-design-20261030/font-dropdown-spec.md`](mobile-design-20261030/font-dropdown-spec.md)(아스트라 최종안).

---

## 1. 기본 원칙

1. 건강정보가 게임 요소보다 우선한다.
2. 위험도(질환 예측 확률), 위협도, 공략 점수는 서로 다른 값으로 명확히 구분한다.
3. 위험을 과도하게 자극적으로 표현하지 않는다.
4. 게임 요소는 접근성을 높이는 보조 수단으로 사용한다.
5. 의료 고지와 안전 안내는 눈에 띄되 공포감을 주지 않는 톤을 사용한다.
6. 동일 의미에는 동일한 색·형태·간격 규칙을 사용한다.
7. 한 코드로 모든 폭을 맞춘다(반응형). 모바일 전용 화면을 따로 만들지 않고 아래 기준 폭에서 규칙을 바꾼다.

## 3. Typography

### 글꼴

- 본문: `Pretendard`(`frontend/docs/prototype/assets/v4-2.woff2`). 대체 순서 `Pretendard, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`. 웹폰트가 늦거나 실패해도 한글을 시스템 글꼴로 읽게 한다
- 게임 표현: `Adventure` = Black Han Sans(`v4-1.ttf`). 데스크톱 제목과 로고(DangoKiller · 당고킬러)에만 쓴다
- 모바일은 제목도 Pretendard 다. Black Han Sans 는 더 가는 굵기가 없어 실제 폰에서 뭉개진다
- 대체 후보(Noto Sans KR · SUIT)는 실제 모바일 비교 전까지 바꾸지 않는다. 바꿀 때는 한 가지만 로컬 자산으로 두고 버전·라이선스를 고정한다

### 제목

| 단계 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 화면 제목 `h1` | Adventure 700 / 28px | Pretendard **800** / 28px |
| 섹션 제목 `h2` | Adventure 700 / 18px | Pretendard 700 / 18px(건강정보 입력 화면만 20px) |
| 소제목·카드 제목 `h3` | Adventure 700 / 15px | Pretendard 700 / 15px |

- 화면 제목은 한 화면에 하나다. 카드 안의 이름(예: `Lv. 1 모험가`)은 `h2`·`h3`다
- 제목 크기·굵기는 위 표만 쓴다. 컴포넌트마다 제목 글자 크기를 따로 정하지 않는다
- 필수·선택 표시는 제목 뒤에 작은 글자로 붙인다(`*필수` 불투명 `#C52E3D`, `(선택)` 회색)

| 제목 규칙 예외 | 이유 |
| --- | --- |
| 첫 화면·가입 안내·예측 대기 문구(`.hero-copy` · `.signup-copy` · `.waiting-copy`) | 화면 제목이 아니라 큰 안내 문구다 |
| 레벨 숫자(`.growth-level`) | 숫자 강조다 |
| 작은 아이템 카드 이름(`.reward-tile` · `.draw-result` · `.room-prop`) | 좁은 카드 안에 들어가야 한다 |
| 메뉴 창 제목(`#app-menu`) | 화면이 아니라 메뉴다 |

- 검사: `scripts/frontend/v5-live-browser.test.mjs` "모든 화면의 제목은 디자인 규칙의 크기·굵기·글꼴을 따르고 화면 제목은 하나다"가 390px·1440px에서 모든 화면과 탭을 잰다. 예외를 늘릴 때는 이 표와 테스트를 같이 고친다

### 본문·보조·입력

| 용도 | 데스크톱 | 모바일 최소 |
| --- | --- | --- |
| 본문·설명·라벨·버튼·카드 안 이름 | 12–14px | **14px** |
| 보조 표시·배지·지도 이름표·전투 점수판 | 11–12px | **12px** |
| 입력·선택 칸(`input` · `select` · `textarea`)·선택 항목 | 16px | 16px |
| 메뉴 창 항목 / 구분 제목 | 14px / 12px | 14px / 12px |

- 입력 칸 16px 는 본문 규칙의 예외다. iOS Safari 는 16px 보다 작은 칸에 초점이 가면 화면을 확대한다
- 줄높이: 본문 1.5, 설명·오류 1.5–1.6
- 숫자 강조: 주요 확률 Bold 28px, 타이머 Bold 52px
- 숫자는 단위를 함께 쓰고 이름을 생략하지 않는다(`위협도 72`, `공략 점수 40`, `고혈압 위험 31%`)

### 모바일 굵기

| 대상 | 굵기 |
| --- | --- |
| 화면 제목 | 800 |
| 섹션·카드 제목, 숫자·배지(레벨·위험도 %·공략 점수·단계 번호) | 700 |
| 버튼·탭·링크·상단 제목, 본문 속 굵은 이름·라벨 | 600 |
| 본문 | 400 |

데스크톱은 시안 굵기를 그대로 쓴다.

## 4. Color

### Base

v5 HTML의 `:root` 토큰을 그대로 쓴다.

- Ink(본문): `#202C47`
- Navy(제목·Primary CTA): `#1F2B3A`
- Muted(보조 설명): `#64707A`. 모바일 화면 설명 문단은 한 단계 진한 `#4F5A66`
- Border: `#E1E3EE`. 모바일 카드 테두리는 `#D3D7E6` + 옅은 그림자 `0 1px 3px #14213D14`
- Surface/Card: `#FFFFFF`, 화면 배경 `#F7F8FC`
- 앱 바깥 배경: 어두운 남색 `#14213D` 위에 모험 세계 그림

### Semantic

- Primary / CTA: Deep Navy `#1F2B3A`
- Game / Accent: Purple fill `#705EE0` / text `#5542B5` / soft(lilac) `#F0ECFE`
- Reward / RARE: Gold `#E9BD77`, RARE 카드 배경 `#FFF9E9`·테두리 `#D3B462`·글자 `#8B651A`
- Success / Completion: Mint fill `#2E7A57` / text `#235F40` / soft `#E6F7ED`
- Caution / Behavioral factor: Amber fill `#B87826` / text `#7A4A12` / soft `#FBF0D4`
- Elevated risk / Attention: Coral fill `#C7544D` / text(threat) `#9E342F` / soft `#FDE8E3`
- Informational / Prediction: 위험도 숫자 `#5266AD`

### 의미 고정

- Coral: 높은 위협·주의가 필요한 값
- Purple: 공략 점수·게임 진행·지금 위치(메뉴의 지금 화면)
- Mint: 완료·진행 중·안전 확인·성공
- Amber: 의료 고지·생활행동 주의
- Blue: 예측 정보·정보성 상태
- Gold: 보상의 희귀도(RARE)·성장 재료. 건강 상태에는 쓰지 않는다

캐릭터는 비세라·알데·코티니·스파이크 네 마리이며 일러스트(`evolution-sprites.webp`·`v4-3.png`)로 구분한다. 캐릭터별 고유색 토큰은 두지 않는다.

### 대비

- 글자 대비는 **실제 배경 기준** 4.5:1 이상이다. 색 토큰을 썼다고 통과로 보지 않는다(밝은 회색 배경 위 `#64707A` 는 4.78:1, 72% 투명 빨강은 3.3:1 로 모자랐다)
- 상태를 알리는 경계·아이콘은 주변과 3:1 이상
- 흰 배경의 핵심 텍스트에는 fill 색보다 진한 text 토큰을 쓴다. 의료 고지·예측 수치·경고·성공 라벨은 text 토큰을 우선한다
- 색만으로 상태를 전달하지 않고 글자 라벨을 함께 쓴다

## 5. Spacing & Radius

- 간격 단위: `8 / 12 / 16 / 20 / 24`. 같은 그룹 안 8–12, 카드 안 14–16, 카드 사이 14–16, 화면 좌우 20(모바일 건강정보 입력 20), 주요 섹션 사이 20–24
- 모서리: 버튼 12–14px, 카드 18–22px, 작은 칸(입력·보상 카드·위험도 칸·선택 행) 10–14px, 배지·칩 완전 둥글게
- 누르는 영역은 모두 44 × 44px 이상

## 6. 공통 컴포넌트

### 버튼

- Primary: Deep Navy 배경, 흰 글자, 14px(모바일 600), 높이 44–48px(건강정보 입력의 다음·예측 보기는 52px). 주요 진행 CTA에만 쓰고 한 화면에 원칙적으로 하나
- Secondary: 옅은 회색 배경, Navy 글자
- 예: Primary `내 위험요인 보기` · `타이머 시작`, Secondary `이 추천은 나와 맞지 않아요` · `오늘 기록 보기`

### 카드

- 흰 배경, 1px 테두리, 모서리 18px, 안쪽 14–16px. 제목 → 핵심 값 → 설명 순서
- 상태 카드는 semantic soft 배경(Success Mint · Warning Amber · Prediction Blue · Game Purple)

### 상태 배지

둥근 배지(위아래 3px · 좌우 10px, 12px 600)로 상태를 글자와 색으로 함께 보인다.

| 상태 | 배경 | 글자 |
| --- | --- | --- |
| 진행 중 | `#E2F5EA`(+ `#B6E3C9` 안쪽 테두리) | `#1D6A45` |
| 기간 종료 | `#EEF0F6` | `#4A5470` |
| 중단 | `#FDECEA` | `#9E342F` |
| 시작 전 | `#F0ECFE` | `#5542B5` |

### 전투 칩(추천·진행 중 챌린지)

- 공격 이름(`걷기 공격`·`근력 공격` 등)만 보이는 작은 둥근 상자다. 높이 44px, 좌우 16px, 14px 600 Pretendard, 한 줄
- 챌린지 이름·상태는 화면 읽기 전용 글(`.sr-only`)로만 둔다. 누르면 상세로 가서 거기서 보인다
- 진행 중: 민트 채움(`#3A9A74 → #1D6A59`) + 밝은 점. 시작할 수 있음: 반투명 흰 테두리 상자. 지금 시작할 수 없음: 흐리게(0.5)
- 줄바꿈해 모두 보인다(가로로 잘리지 않음). 모바일은 지금 누를 수 있는 칩(진행 중·시작 가능)만 남긴다

### 선택 입력 펼침 목록(모바일)

진단·복약·음주·외식은 모바일에서 브라우저 선택 창 대신 펼침 목록으로 받는다. 선택 창 목록은 기기마다 다르게 뜨고(아이폰 아래쪽 휠, 안드로이드 가운데 창) 페이지 글자 크기를 따르지 않는다. 데스크톱은 select 를 그대로 쓴다.

- 구조: 질문 라벨(16px 600) 아래 8px 에 트리거 버튼, 누르면 같은 폭의 1열 라디오 목록이 바로 아래 문서 흐름에 펼쳐져 뒤 필드를 밀어낸다. 팝업·바텀시트·그림자 없음. 질문 사이 24px
- 치수: 트리거·행 52px 이상, 글자 16px(선택값 500, 고른 행 600), 좌우 16px, 모서리 12px
- 색: 미선택 문구 `#64707A`, 고른 행 `#F0ECFE` 배경 · `#5542B5` 글자 + 체크, 트리거 경계 `#848B9F`, 펼침·초점 `#5542B5`(외곽선 2px), 오류 `#9E342F` 2px
- 동작: 한 번에 한 목록. 다른 트리거를 누르면 앞 목록은 닫히고(고르던 값은 버림) 새 트리거가 손가락 아래에서 움직이지 않게 스크롤을 보정한다
- 임시값·확정값: 열린 동안 라디오 값은 임시값이다. 행 누르기·Enter·Space 로 확정하고 닫은 뒤 트리거로 초점을 돌린다. Tab 으로 벗어나거나 목록 밖을 눌러도 확정, Esc·같은 트리거는 버린다. 방향키로 '마시지 않음'을 지나가도 음주량을 숨기거나 지우지 않는다. Enter 로 폼이 제출되지 않는다
- 미선택은 '선택해 주세요'(빈 값). '최근 4주 동안 마시지 않음' 확정 시에만 음주량을 숨기고 0 으로 보내며 '음주량 입력은 생략해요.'를 보인다. 다시 음주로 바꾸면 음주량을 다시 고르게 한다
- 오류: '○○을 선택해 주세요.'를 질문 아래 14px 로, 트리거에 `aria-invalid` · `aria-describedby`. 제출 때 오류면 그 트리거로 초점을 옮기고 목록을 연다
- 접근성: 트리거는 `button` + `aria-expanded` · `aria-controls`(이름은 질문과 현재 값), 목록은 `fieldset` + `legend` + 같은 `name` 의 라디오. combobox · menu 역할을 섞지 않는다(W3C Disclosure 패턴)

### 하단 메뉴(모바일)

- 늘 보이는 아래 띠. 높이 60px(+기기 아래 안전 여백), 좌우 8px 띄우고 1px 테두리 `#D6D9E8` · 모서리 16px · 옅은 그림자
- 항목 높이 44px, 아이콘 18px, 글자 12px 600. 지금 화면 항목은 `#F0ECFE` 배경 + `#C9BFF5` 테두리 + `#5542B5` 글자(`aria-current="page"`)
- 받을 보상이 있으면 가방에 빨간 점. 데스크톱은 왼쪽 세로 메뉴

### 안내 띠(`#live-feedback`)

화면 맨 위에 붙는 한 줄 안내(성공 Mint soft, 오류 Coral soft). 전투 화면에서 띠가 보이면 전투 장면은 남은 높이에만 맞춘다(카드가 화면 밖으로 밀리지 않게).

## 7. 값 표현

### 위협도 · 공략 점수

- 위협도: 0–100, 재예측·재측정 때 갱신, 분모 없이 `위협도 72`, Coral text `#9E342F` 중심
- 주간 공략 점수: 목표 100, 월요일 00:00 KST 초기화, 100 초과 누적, 미달 불이익 없음, Purple text `#5542B5`, 퍼센트 기호 금지(`이번 주 공략 점수 40 / 100`)
- 위협도와 공략 점수를 같은 막대에 겹치거나 `공략 점수 40 → 위협도 -40` 처럼 차감 관계로 보이게 하지 않는다. 재측정은 `위협도 78 / 공략 40 → 재측정 → 새 위협도 56` 처럼 별도 전환으로 보인다

### 질환 예측

모험 지도 위 위험도 칸과 캐릭터 도감 기여요인 Top3 가 나눠 맡는다.

- 반드시: 질환별 상태, 미진단 질환의 예측 확률, 진단 질환의 `진단 관리 중`, 주요 기여요인, 직전 대비 변화(같은 모델의 직전 예측이 있을 때만 `직전 대비 +0.3%p`), 의료 고지
- 부분 진단: 진단한 질환은 `진단 관리 중`, 나머지만 예측. 둘 다 진단이면 예측 확률 생략

## 8. 화면별 기준

v5 화면은 14개다. 주소의 화면 이름은 괄호 안과 같다.

### 로그인(`login`) · 회원가입(`signup`)

- 배경은 영상 한 겹이다. 영상 안에 캐릭터가 있으므로 영상이 실제로 재생되는 동안 대체 그림(스프라이트·탐험가)은 숨기고, 자동 재생이 막히거나 모션 줄이기일 때만 보인다
- 문구 뒤는 밝은 막(위쪽 46% 까지 불투명도 약 0.9)으로 받치고, 부제는 `#26305A` 500 + 흰 번짐 그림자
- 로고(DangoKiller · 당고킬러)만 Adventure

### 건강정보 입력(`health` · `health2` · `health3`) · 예측 대기(`waiting`)

- 입력 오류는 해당 칸 아래에 보인다. 검진정보는 선택 단계임을 제목에 밝힌다
- 모바일: 좌우 20px, 섹션 제목 20px, 설명·기준 기간·오류 14px, 선택 입력은 6절 펼침 목록, 가족력 체크는 22px + 누르는 영역 44px
- 밝은 회색 배경 위 설명·비활성 단계 이름 `#64707A`, `*필수` 불투명 `#C52E3D`(대비 4.5:1)

### 모험 지도(`risk`)

위험도 칸(확률·직전 대비) / 마을별 캐릭터와 위협도 / 의료 고지. 산정되지 않은 마을은 잠근다.

### 캐릭터 도감(`monsters`)

기여요인 Top3 / 캐릭터 / 현재 위협도 / 이번 주 공략 점수 / 산정 설명 / 봉인 상태(`state` · `sealed_at` · `seal_count`).

### 전투와 챌린지(`reco`)

- 핵심: 위협도(재측정 때 바뀐다는 안내) / 공략 점수 / 진행 중·추천 챌린지 / 제외한 챌린지
- 챌린지는 6절 전투 칩으로 아래에 줄바꿈해 모은다. 진행 중 칩이 먼저다. 오른쪽 위 `공략 도우미`로 대화형 고르기(13절)에 간다
- 모바일: 칩 묶음 높이를 재서(`--battle-strip`) 그 위 남은 높이에 모험가(왼쪽)와 캐릭터(오른쪽)를 같은 바닥선에 나란히, 잘리지 않게 높이에 맞춰 줄여 세운다. 안내 문구는 칩 바로 위(높이 610px 이하 화면에서는 숨김)이고, 안내 문구가 보이는 화면에서는 그만큼 둘을 올려 발이 가리지 않는다
- `나중에 할게요` · `해당 없어요`는 실패나 거절과 다른 개념이라 중립적으로 보인다

### 오늘의 공략(`today`)

챌린지 상세(목표·인증 방법·난이도·하루 XP·안전 안내) / 수행 상태 / 인증 / 중단.

### 나의 성장(`progress`) · 캐릭터 변화 도감(`evolution`) · 수행 후 변화(`evolution-complete`)

- 경험치·레벨 / 월별 수행 도장 / 건강 기록 / 캐릭터 외형 단계. 외형 단계 기준이 정해지기 전에는 미리보기로 보인다
- 히스토리 카드: 왼쪽 열은 캐릭터 그림(데스크톱 110px, 모바일 64 × 80px), 오른쪽 열은 위에서 아래로
  1. 공략 이름(`비세라 공략`) + 상태 배지(6절) · 그 아래 기간
  2. 가는 구분선 뒤 주차(`1주차`, Purple 15px 700) + 날짜(12px Muted)
  3. 미션 목록: 왼쪽 정렬 행(배경 `#F6F5FB`, 모서리 10px), 이름은 왼쪽, 완료 횟수(`1회 완료`)는 오른쪽 둥근 배지

### 가방 · 나의 보상(`rewards`)

받을 보상 표시 / 카드 뽑기 / 꾸미기 / 성장의 조각과 아이템 단계. 12절을 따른다.

## 9. 인증 화면 · 의료·안전 안내

- 오늘의 공략 화면에서: 현재 챌린지명, 오늘 목표, 이번 주 진행, 인증 방식, 완료 보상, Primary CTA
- TIMER: 남은 시간을 가장 크게, 중간 종료는 완료로 인정하지 않는다
- PHOTO: AI 판정 없음, 비공개 저장, `evidence_url` 만 기록에 연결
- 의료 고지: Amber soft 배경 + `의료 고지` 라벨, 진단이 아니라는 사실을 명확히
- 운동 전 안전 확인: 운동형 챌린지 시작 직전에 보이고 답은 저장하지 않는다(`safety_confirmed=true` 는 시작 시점 서버 검증용)

## 10. 공통 상태

- Loading: 예측은 접수 뒤 대기 화면에서 2초마다 확인(최대 60회, `결과 다시 확인`으로 다시 시작). 자동으로 다시 제출하지 않는다
- Error: 내부 에러 코드 원문을 보이지 않는다. 해결할 수 있는 설명 + 다시 시도나 이전 화면 CTA. 입력·연결·실패를 구분하되 톤은 같게
- Empty: 오류가 아닌 정상적인 '없음'(챌린지 시작 전·캐릭터 미등장·기록 없음)은 설명 + 다음 행동 CTA

## 12. 보상 표시

- 보상은 실천 보상이다. 건강이 나아졌다는 뜻으로 보이게 하지 않고 `위험도` · `위협도`와 연결하지 않는다

## 13. 공략 도우미(질의 챗봇) 화면

> 구현: 2026-10-30, 화면 이름 `chat`(`frontend/v5/app.mjs` 의 공략 도우미 묶음, `live.css` 공략 도우미 묶음). API 는 `/challenge-chat`(대화) · `/challenge-chat/select`(고르기).

챗봇은 챌린지를 **고르는 것을 돕는 대화**다. 건강 상담이 아니다. 대화로 정보를 모으고 고른 결과는 전투 카드와 같은 상세·시작 흐름(오늘의 공략)으로 연다. 새 색·새 글꼴을 만들지 않는다.

### 들어가는 길

- 전투 화면 오른쪽 위 `공략 도우미`(왼쪽 `← 마을 지도`와 같은 높이·모양, 모바일 44px)
- 메뉴 `공략 도우미 · 대화로 챌린지 고르기`, 오늘의 공략 목록의 `공략 도우미에게 묻기`

### 화면 구성(휴대폰 390px 기준)

- 위에서 아래로: 상단바(뒤로·`공략 도우미`) → 대화 목록(스크롤, 맨 위에 `h1` `공략 도우미`와 한 줄 소개, 첫 안내 말풍선) → 의료 안내 한 줄 → 주 버튼 `이 대화로 챌린지 고르기` → 입력창
- 대화 화면에서는 하단 메뉴를 숨기고 입력창이 맨 아래에 붙는다
- 화면 제목 `h1` 은 `공략 도우미` 하나, 고른 결과 묶음 제목은 `h2` `대화로 고른 챌린지`
- 320px 에서도 가로로 넘치지 않는다. 말풍선은 줄바꿈한다

### 말풍선

| 구분 | 위치 | 배경 | 글자 | 모서리 |
| --- | --- | --- | --- | --- |
| AI(공략 도우미) | 왼쪽, 최대 폭 85% | Surface + Border 1px `#E1E3EE` | Ink `#202C47` | 18px, 왼쪽 위만 6px |
| 사용자 | 오른쪽, 최대 폭 80% | Purple soft `#F0ECFE` | Ink `#202C47` | 18px, 오른쪽 위만 6px |
| 고정 안내(꺼짐·오류) | 왼쪽 | Surface + Border | Muted `#64707A` | AI 와 같음 |
| 건강 판단 거절 안내 | 왼쪽 | Amber soft `#FBF0D4` | Amber text `#7A4A12` | AI 와 같음 |

- 사용자와 AI 는 색만이 아니라 위치와 라벨로도 구분한다(AI 묶음 위 `공략 도우미` 라벨 12px, 사용자 말풍선에는 화면 읽기용 `나:`)
- 같은 사람 말풍선 사이 6px, 말한 사람이 바뀌면 14px
- 서버 고정 문장(`off` · 오류 · 건강 판단 거절)은 그대로 보이고 오류를 Coral 로 칠하지 않는다
- 본문 14px · 줄높이 1.6, 말풍선 안에서는 굵게·색 강조를 쓰지 않는다. 입력창 글자 16px

### 결과(`/challenge-chat/select` 의 `mode`)

| `mode` | 보여 줄 것 |
| --- | --- |
| `conversation` | AI 말풍선에 `answer` → 그 아래 `h2` `대화로 고른 챌린지` + 챌린지 1\~3개. 각각 `고른 이유` 라벨(12px Muted) + `reason` 한 줄 |
| `ask` | AI 말풍선 안에 `questions` 마다 선택지 칩(높이 44px, 고르면 Purple soft + Purple 테두리). 식후 걷기 `점심·저녁 모두 돼요`·`점심만`·`저녁만`·`어려워요`, 짬 움직이기 `하루 세 번`·`그보다 적게`·`어려워요`, 나머지 `할 수 있어요`·`어려워요`. 몸을 쓰는 질문에는 `몸 상태 때문에 어려워요`(제한) 를 더한다. 자유 입력으로 답받지 않고, 물은 질문에 모두 답하면 바로 다시 고른다 |
| `rules` | `h2` `추천 챌린지` + 위에 `지금은 대화로 고르지 못해 추천 목록을 보여 드려요.`(12px Muted) |
| `hold` | 10절 Empty 상태. 설명 + `모험 지도로 가기` |
| 슬롯이 다 참(409 `CHLG_RECOMMENDATION_UNAVAILABLE`) | `hold` 와 같게 서버 안내 문장 + `모험 지도로 가기`, 입력을 막는다. 오류색을 쓰지 않는다 |
| 꺼짐(`mode: off`) | 서버 안내 말풍선 + `추천 목록 보기`, 입력을 막는다 |

- 결과 항목: 흰 카드(테두리 `#D3D7E6`, 모서리 16px) 안에 챌린지 이름(16px 600) · 공격 이름과 하루 XP(12px Purple) · `고른 이유`(12px Muted) · 이유 한 줄(14px)
- 누르면 전투 화면과 같은 상세·시작 흐름(운동 전 안전 확인, 예정 이용일, CHLG-05)으로 `오늘의 공략`에 간다
- 근거 카드 ID·출처는 사용자에게 보이지 않는다
- 시작하려고 전투 화면으로 보내지 않는다(전투 화면은 열 때마다 규칙 추천을 새로 만들어 대화 추천을 가린다). 보내야 하면 새로 만들지 않는 경로(`keepRecommendations`)로 연다

### 입력·상태·개인정보·접근성

- 주 버튼(Primary 48px)은 AI 답이 한 번 온 뒤부터 보이고 결과가 나오면 숨긴다
- 입력창 1\~4줄 `textarea`(최대 120px), 최소 44px, 모서리 14px, 보내기 44 × 44px(빈 입력·기다리는 동안 꺼짐). Enter 로 보내고 Shift+Enter 는 줄바꿈, 한글 조합 중 Enter 는 보내지 않는다. 메시지당 400자(350자부터 `n / 400`), 대화 12개까지이고 다 차면 `대화가 길어졌어요. 지금까지 내용으로 골라 볼까요?`와 주 버튼만 남긴다
- 답 기다릴 때 `답을 만들고 있어요` + 점 3개(모션 줄이기면 멈춤). 실패한 요청은 자동으로 다시 보내지 않고 `다시 보내기`
- 대화는 메모리에만 둔다(localStorage · sessionStorage 금지). 입력창 위에 늘 `건강 수치·질환 판단은 하지 않아요. 진단·치료는 의료진과 상의해 주세요.`
- AI 답 옆에 위험도·위협도·예측 확률을 함께 보이지 않는다
- 대화 목록 `role="log"` + `aria-live="polite"`, 모든 칩·버튼·입력창은 키보드로 닿고 초점 테두리가 보인다
