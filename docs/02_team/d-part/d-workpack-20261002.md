### 최신 요구사항으로 바뀐 부분

- CHLG-002: 1주차 2개, 2주차부터 한 방향을 추가해 최대 3개, 3주차 이후 추가 없이 유지. 기존 진행 항목이 있으면 남은 슬롯만 사용.
- CHLG-011: 미션 시작 후 4주가 지나면 수행 여부와 관계없이 종료. 수행률 충족 여부는 별도 습관 졸업 기록. 미달 자체로 강제 재제시·난이도 조정하지 않음.
- CHLG-012: 대화형 추천은 최대 3개 질문, 승인된 코드·난이도만 사용. factor_key는 마스터에서 조회. 실패 시 **기존 규칙 기반 추천**으로 대체.
- RECO-006: 한 번에 한 캐릭터 공략, 갱신된 위협도가 가장 높은 대상 자동 선정 및 도감 수동 변경. 4주 종료 후 재측정 반영.
- RECO-007~009: 봉인 기록은 회수하지 않음, 재측정 상승 별도 표시, 외형은 28일 누적 진행률, 전체 봉인 후 종료·상승 시 재공략.

이전 공유 미션 후보 v2의 ‘고정 4주 배정 없이 선택·유지’ 설명과 기획안 v0.1의 ‘기존 개별 기간 유지·수동 선택 fallback’은 위의 최신 요구사항과 달라졌다. 아이디어 후보는 재사용하되 이전 문장을 현재 확정 정책으로 인용하지 않는다.

### 우선 실행·합의 순서

1. 최신 v1 실물 확보·19행 대조: 현재 미확인. v0를 v1로 이름만 바꿔 seed하지 않음.
2. 걷기·좌식 지원 코드 후보는 CH_WALK_AFTER_MEAL, CH_WALK_ONE_STOP, CH_STAND_HOURLY. 최종 자동 추천 허용은 승인 상태·모델 요인 경계·사용자 조건에 따라 결정.
3. 식후 점심/저녁만 가능한 선택과 하루2회 인증의 불일치를 먼저 정리. 좌식은 매시간 제목과3회 목표를 맞춤.
4. CH_COUNT_DOWN 관찰형 계약, 계단·국물·흡연지연 supporting 제안, NULL factor 점수·비활성 정합성은 검토 승인 후 변경.
5. 최신 개별28일과 주차 투입 계약을 반영한 마스터가 준비되면 시작·만료 구현을 진행.

## 5. 행동 임계값·weight 검토안

이 표는 모델·운영 승인을 대체하지 않는다. 서비스 입력의 유효성, 모델 지원 여부, 추천 조건 승인을 모두 확인해야 한다. 미응답·미채택·조건 미정은 유효한0과 구분한다.

| factor | 조건 제안 | 보류·제약 |
|---|---|---|
| smoking_current | 유효한1만 흡연 후보 | 0=현재 비흡연, 과거흡연 구분 불가. NULL 보류 |
| alcohol_frequency | 유효한2~6은 절주 후보,1 제외 | 위험음주 판정 아님. 현재 원문항 기간과 서비스4주 차이 확인 |

## 7. 대화·검증·등록 연결 검토

신규 DB/API의 확정 명세나 구현 코드를 복제하는 문서가 아니다. 병주님 기획안·최신 CHLG-012를 기존 D 기능에 연결하기 위한 체크리스트다.

1. 사용자 본인 답변·진행/제외 상태를 읽고 질문은 최대3개. 필수정보가 부족하면 추정하지 않음.
2. 승인된 카드만 검색, 팀 기준표와 연결되는 코드·난이도만 전달. draft 카드12개는 운영 색인에 넣지 않음.
3. 제안 JSON의 코드 존재·활성·난이도·관련 근거·권한·제외·기회·중복·target·주차·남은슬롯 검증.
4. factor_key·목표·단위·기간·보상은 서버가 승인 마스터에서 조회. 모델이 제안한 임의factor나factor_score를 신뢰하지 않음.
5. 검증 통과 후보만 conversation 추천에 등록. 같은 사용자·주기 재요청 중복 방지 기준은 cycle 식별 계약과 함께 확정.
6. 사용자 시작 동의와 마스터 안전확인을 받은 뒤 기존 시작 함수 호출. 미시작 추천을 active로 만들지 않음.
7. 실패는 최신012의 규칙추천으로 대체. 규칙 근거도 없으면 보류. 기존 수동 경로는 별도로 유지하되 자동 대체 구현으로 과장하지 않음.

현재 난이도ENUM과 숫자 difficulty_value의 변환, 추천 출처conversation의 실제 코드 반영, 대화·카드버전 추적, cycle의 중복등록키는 아직 구현 완료가 아니다. 승인된 난이도별 목표가 없으면 현행 고정 원형만 사용한다.

개인 대화·건강기록은 공통 코퍼스에 넣지 않는다. 추천 입력은 인증된 사용자 문맥이며 이름·이메일 등 불필요 정보와 안전확인 응답은 저장 범위를 확장하지 않는다.

- 실패: 근거/응답/JSON 실패 때 규칙대체 또는 보류. 사용자 데이터 변경·중복추천·중복보상0건 목표.
- 주기: E17~19는 산식·계약 합의 전 기대 실행값을 확정할 수 없음. 임의가정으로 통과 처리하지 않음.
- 결과 기록: 실제 실행 전 ‘90% 달성’, ‘0건 검증’으로 발표하지 않음. fixture 승인 뒤 결과를 채운다.

## 9. 남은 순서

1. A/D: 최신 마스터 실물과 난이도별 목표·28일기간, 공략cycle·target전환·후반direction 순서·졸업 산식 확인.

3. D: 승인된 키를 걷기·좌식 카드에 확정 연결. B는 모델 입력·추천요인 경계를 검토하고 카드 검토담당을 팀에서 지정.
