# CHLG-05·CHLG-10 후속 구현 안내

기준: PR #42·#43이 반영된 main `92bea77`. 공통 프론트 전체 패치를 다시 적용하지 않는다.
실행은 기존과 같이 `docker compose up -d`와 `frontend/`의 `npm ci`, `npm run dev`를 사용한다.
화면 주소는 `http://127.0.0.1:5173/`이다.

## CHLG-05: 예정 이용일

- `POST /api/v1/user-challenges`의 `scheduled_dates`는 KST `YYYY-MM-DD` 문자열 배열이다.
- `context_type=event` 카드가 선택됐을 때만 입력하고, 한 날짜 이상 확인해야 시작한다.
- 중복·과거·주기 종료일 이후 날짜·잘못된 형식은 `VALIDATION_ERROR`로 거절한다.
- 일반 일일 카드에만 예정일을 보내는 것도 거절한다.
- 이벤트 카드의 예정 기회는 확인한 날짜와 목표 회차 수로만 생성한다. 매일이나 평일로 추정하지 않는다.
- 날짜 목록은 해당 사용자 미션의 `goal_config_snapshot.scheduled_dates`에 고정한다.
- 여러 카드를 함께 시작하면 이벤트 카드들에 같은 이용일 목록을 사용한다. 카드별 별도 일정은 이번 계약에 없다.
- 초기 28일·D7 추가 시 21일·공통 D28 종료는 유지한다. 잘못된 입력이면 선택한 모든 미션과 주기 변경이 취소된다.
- `CH_WALK_ONE_STOP`을 추천 후보에 다시 포함했다. 마스터 난이도·목표는 바꾸지 않았다.

## CHLG-10: 시작 전 대상 변경

- `PATCH /api/v1/attack-cycles/current/target`, 본문 `{user_monster_id}`.
- `draft`이고 시작한 미션이 없는 주기만 변경한다. 진행 중·중단 이력이 있는 시작된 주기를 되돌리지 않는다.
- 본인 소유·활성 마스터·측정된 위협도·공략 가능 상태의 대상만 허용한다.
- 다른 대상으로 바꾸면 같은 주기의 미응답 추천만 무효화한다. 거절·수동 제외 이력은 보존한다.
- XP·레벨·공략 점수·봉인 기록은 수정하지 않는다. 같은 대상을 다시 지정해도 추천을 지우지 않는다.
- 시작과 변경은 기존 사용자 행 잠금을 공유한다. 실제 MySQL에서 경합 테스트를 실행해야 한다.
- 도감 응답에 `user_monster_id`, `target_change_allowed`를 추가했다. `is_target`은 draft/active 현재 주기로 계산한다.
- 도감에서 서버가 허용한 대상만 변경 버튼을 표시하며, 변경 후 새 목록을 조회한다.

## C 폴링 화면 연결

공통 컨텍스트에 `predictionReady`를 제공한다. 새 예측을 제출할 때 `predictionReady.clear()`를 호출하고,
실제 `pending` → `done` 확인 직후 `predictionReady.markDone(result)`와 `router.navigate('reco')`를 연결한다.
`result`에 `status: 'done'`과 양의 정수 `prediction_id`가 필요하다. C 폴링 화면 구현 자체는 C 담당 범위다.

완료 표시는 메모리의 5초짜리 일회성 값이다. 해당 최초 추천 호출에서만
404 `PRED_NOT_FOUND` 또는 409 `CHLG_RECOMMENDATION_UNAVAILABLE`을 1초 간격으로 최대 2회 더 호출한다.
일반 오류·다른 코드·사용자가 누른 다시 확인·시작·대상 변경·수행 인증에는 적용하지 않는다.
화면 이탈·계정 변경 이후 예약 호출을 중단하며, 최종 오류는 서버 `error.message`를 표시한다.
409 세부 코드 분리는 2단계 범위로 유지했다.

## 원본 시트 반영용 확인 문구

API 명세 사본을 임의 수정하지 않았다. 원본 시트의 두 “D 확인 필요” 항목에는 아래 내용을 반영하면 된다.

| 항목 | D 확인 내용 |
| --- | --- |
| CHLG-05 | 구현 완료. 이벤트형 카드는 사용자 확인 예정 이용일 필수. KST 날짜·중복·기간 검증 후 해당 날짜의 예정 기회만 생성. |
| CHLG-10 | 구현 완료. 1단계는 챌린지 시작 전 draft 주기에서만 본인 공략 가능 대상으로 변경. 기존 미응답 추천 무효화, 수행·XP·봉인 보존. 진행 중 변경은 후속 범위. |

도감·추천 응답의 추가 필드도 명세에 반영할 대상이다. 새 테이블·컬럼·마이그레이션은 없다.

## 검증 범위

- 프론트 단위 검사: 완료 표시 없는 요청·만료·최초 요청·허용 오류·계정 변경·화면 이탈.
- 브라우저: 이용일 확인·중복 제거·정렬된 시작 요청·320px·도감 변경·최종 서버 오류.
- 앱: 잘못된 날짜의 전체 롤백·추가 주기의 종료일·타인 대상 거절·시작 후 변경 거절·오래된 카드 시작 거절.
- MySQL 전용: 기존 중단/재시작 경합과 새 시작/대상 변경 경합. SQLite 통과로 이 두 검사를 대신하지 않는다.
- 실제 로그인·DB·워커·C 폴링을 함께 돌리는 서비스 통합 검증과 사진 업로드 연결은 후속 작업이다.
