# 위협도 산정 요인 표시 계약

2026-10-15 기준. 기준 커밋: `5509c50` (#61 머지).
팀 공유·C 확인 후 원본 명세에 반영하고 로컬 구현했다. 실제 DB 적용·머지는 별도다.
최신 상태는 d-team-followup-20261015.md를 따른다.

## 현재 확인한 사항

- `ImpactService._contribution_score`는 지원되는 질환×요인의 정수 위협도 중 최댓값과 출처만 반환한다.
- `user_monsters`에는 위협도·출처·건강기록 ID·개인 기여도 출처일 때 예측 ID가 저장된다.
- 최댓값을 만든 요인, 질환별 후보 점수, 산정 모델 버전·정책 버전은 저장되지 않는다.
- `MonsterService.list_mine`은 해당 산정 요인을 응답하지 않는다.
- 기존 점수는 새 산정이 불가능하면 보존한다. 최신 건강기록이나 현재 모델의 요인을 기존 점수 설명으로 붙이면 안 된다.
- 진단 이력에 따른 전역 점수와 개인 SHAP 점수는 산식이 다르다. 같은 몬스터 안에서도 질환별 출처가 달라질 수 있다.

## 저장 구조 제안

D 소유 `user_monsters`에 nullable JSON 컬럼 `impact_explanation_snapshot`을 추가하는 안을 검토한다.
기존 행은 NULL로 유지한다. 현재 자료로 과거 설명을 역산해 채우지 않는다.

| JSON 항목 | 형식 | 의미 |
| --- | --- | --- |
| schema_version | 문자열 | snapshot 구조 버전 |
| policy_version | 문자열 | 반올림·최댓값·지원 요인 처리 정책 버전 |
| model_version | 문자열 또는 null | 산정에 사용한 모델 버전. 실측이면 null |
| calculated_at | KST 시각 문자열 | 해당 위협도를 저장한 시각 |
| health_record_id | 정수 | 산정 건강기록. 기존 참조와 일치 |
| prediction_id | 정수 또는 null | 사용한 개인 기여도 예측. 전역·실측은 null |
| impact_score | 0\~100 정수 | snapshot이 설명하는 저장 점수 |
| candidates | 배열 | 당시 산정한 질환·요인·정수 점수·출처 목록 |
| winners | 배열 | 저장 최댓값과 같은 모든 후보. 동점을 임의로 하나만 선택하지 않음 |

각 후보는 `disease`, `factor_key`, `score`, `source`를 담는다.
실측 변환 정책이 승인되기 전 스파이크 snapshot은 만들지 않는다.
원시 SHAP·개인 입력값은 이 snapshot에 중복 저장하지 않는다.

## 갱신 계약

1. 기존 산식을 그대로 적용하면서 각 후보의 질환·요인·점수·출처를 함께 확보한다.
2. 점수가 산정되지 않으면 기존 점수·참조·snapshot 모두 보존한다.
3. 유효한 점수가 나오면 기존 사용자 잠금·트랜잭션 안에서 점수·출처·참조·snapshot을 함께 갱신한다.
4. 봉인·공략 점수·타깃 변경 정책은 기존 동작을 따른다.
5. 0점 후보도 산정은 완료된 값이다. 다만 화면에서 위험 증가 원인으로 설명하지 않는다.
6. 사용자 진단 이력이 이후 바뀌어도 저장된 설명을 현재 진단 이력으로 재계산하지 않는다.

## MNSTR-01 응답 제안

기존 응답에 `impact_explanation`을 추가한다. 필드 이름과 타입은 명세 합의 후 확정한다.

- `status`: `available`, `unavailable`, `pending`.
- `available`: 정합성이 확인된 snapshot에서 모델·정책 버전과 winners를 응답한다.
- `unavailable`: 기존 점수는 있으나 snapshot이 없거나 점수·참조가 맞지 않는다. winners는 빈 배열이다.
- `pending`: 현재 표시할 산정 점수가 없다. winners는 빈 배열이다.
- 기존 score/source/참조와 snapshot이 어긋나면 요인 이름을 추정하지 않는다.
- 서버 내부의 건강기록·예측 참조 ID를 화면용 설명 응답에 추가 노출할 필요는 없다.

## 화면 계약

- 양수 점수 + available: “현재 위협도를 대표하는 요인: …”로 표시한다. 질병의 원인으로 단정하지 않는다.
- 동점이면 모든 대표 요인을 표시한다. 같은 요인이 두 질환에 걸리면 질환을 구분한다.
- 0점: “이번 산정에서 위협도를 높인 요인이 없어요”로 표시한다. 보호 효과·질환 부재를 뜻한다고 쓰지 않는다.
- 점수 + unavailable: “이 점수의 개별 산정 요인 정보가 없어요”로 표시한다.
- 미산정 비세라와 보류 스파이크는 #61의 안내를 유지한다.
- 추천 근거는 대표 위협도 요인과 별개다. 실제 추천 결과의 연결 행동 요인만 사용한다.

4. 응답 정합성 검사와 도감 표시 구현 → 프론트·앱·브라우저 검증.
5. C 담당 예측·사진 업로드 API가 준비되면 실제 워커·로그인·업로드 통합 확인.
