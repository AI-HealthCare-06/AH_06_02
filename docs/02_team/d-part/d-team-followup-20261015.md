## 추천 불가 안내 수정

기존 409 코드를 유지하고 error.reason으로 아래 원인을 구분한다.

| reason | 의미 |
| --- | --- |
| model_unavailable | 앱이 읽을 모델 자료 없음 |
| target_unavailable | 공략 가능 대상 없음 |
| slots_unavailable | 주기·동시 진행 제한으로 추가 슬롯 없음 |
| no_additional_candidates | 진행 미션이 있고 현재 남은 후보 없음 |
| no_eligible_candidates | 현재 대상의 승인 후보 없음 |
| no_positive_factors | 현재 기록에서 양수 추천 요인 없음 |

추가 후보·슬롯이 없으면 ‘진행 중인 공략 보기’ 버튼으로 today에 연결한다.
원인이 지정된 409는 예측 직후에도 자동 재시도하지 않는다.
기존 reason 없는 409와 지정된 404의 한정 재시도 규칙은 유지한다.
미션 존재만으로 모델 자료 오류를 후보 소진으로 바꾸지 않는다.

## 사진 연결과 C 코드 보완

C 업로드의 multipart 필드는 photo·user_challenge_id다. 프론트 연결은 이 계약을 사용한다.

- 기존 C 소유권 함수에 PHOTO 종류·현재 수행 기간·연결 공략 주기 active 검사를 추가했다.
- 전체 파일을 무제한 읽지 않고 10 MiB+1만 읽는다.
- Pillow로 JPEG/PNG 실제 형식·손상·과도한 이미지 크기를 검사한다. Content-Type만 신뢰하지 않는다.
- C의 verify_reference(user_id, user_challenge_id, reference)를 D 수행 기록 트랜잭션에서 호출한다.
- 참조값의 사용자·미션 접두사·UUID 형식과 실제 파일 존재·크기를 확인한다. 경로 탐색·심볼릭 링크는 거절한다.
- 임의 문자열, 다른 사용자·미션의 사진, 없는 파일로 수행 보상을 만들지 않는다.
- Nginx API 요청 한도를 11 MiB로 설정해 10 MiB 사진과 multipart 경계를 수용한다. 실제 파일 한도는 서버에서 10 MiB로 검증한다.
- API 전용 evidence_volume을 /app/media/evidence에 마운트한다. nginx에는 이 볼륨을 마운트하지 않는다.
- 서버와 프론트를 함께 포함하므로 사진 연결 기본값을 활성화했다. 서버 없는 이전 환경에는 evidencePhotosEnabled=false가 필요하다.
- 이미지 내용을 운동·섭취 성공으로 AI 판별하지 않는다.

사진 카드 후보 승인 정책은 변경하지 않았다. 1단계에 사진 카드가 없으면 일반 화면에서
사진 기능이 보이지 않는 것이 정상이다. 임의로 마스터를 켜서 운영 추천에 넣지 않는다.
탈퇴 후 증빙 파일 정리 배치는 이번 구현에 포함되지 않는다. A의 보관·삭제 배치 연결은 별도 작업이다.

## 산정 요인 저장·표시

원본 테이블 명세 user_monsters의 17번 nullable JSON 컬럼 impact_explanation_snapshot을 추가하고
테이블 목록 컬럼 수 17, 실제 코드와 어긋나던 last_health_record_id 설명을 맞췄다.
API 원본 MNSTR-01에는 impact_explanation 응답을, CHLG-01에는 reason 계약을 추가했다.
시트 값을 다시 내보내 sync_specs.py로 table-spec.md와 api-spec.md를 재생성했다.
ERD·DDL에 새 JSON 필드를 반영하고 7번 마이그레이션을 준비했다.
시트 값과 기존 서식 보존을 API로 확인했으며 Google 화면의 직접 시각 검사는 하지 않았다.

저장 내용은 산정 시각·모델/정책 버전·점수·출처·참조·질환×요인 후보와 모든 동점 대표 요인이다.
개인·전역 출처가 섞이면 개인 기여도 예측 참조도 snapshot에 보존한다.
점수와 snapshot을 같은 트랜잭션에서 갱신하고, 새 산정이 불가하면 이전 값 둘 다 보존한다.

도감은 snapshot의 점수·출처·참조와 현재 저장 행의 일치를 확인한다.
과거 snapshot이 없거나 불일치하면 unavailable, 미산정이면 pending으로 반환한다.
저장 설명이 있으면 모델을 다시 읽지 않고 당시 대표 요인을 표시한다.
0점은 위협도 증가 요인이 없다는 안내이며 보호 효과나 질환 부재를 뜻하지 않는다.
