# D 대화형 추천 준비·알데 조건 적용안

기준 main: PR #44·#45·#46 및 예시 환경변수 정리 반영 `22f0577`. 10/2 기획 사본은 보존한다.
이번 변경은 새 DB 컬럼이나 공개 엔드포인트를 추가하지 않는다. 기존 추천 화면도 유지한다.

## 구현한 범위와 활성 상태

| 항목 | 상태 |
| --- | --- |
| 현재 마스터에 연결한 C01~C12 카드 JSON | 출처 확인·D 검토 초안. 운영 상태는 모두 draft |

| LLM 구조화 선택·서버 검증 | provider 교체 가능. 실제 OpenAI 호출은 미실행 |
| conversation 내부 저장 | 기존 세 컬럼 사용, 고정 목표 유지, 사용자 확인 전 미션 시작 없음 |

전체 대화형 추천 서비스가 운영 중이라는 뜻이 아니다. 임베딩·벡터 DB 서버 없이 작은 코퍼스의 태그 검색부터 준비했다.
카드의 안내 문구는 서버가 선택한 근거에서 가져온다. LLM이 자유롭게 건강 효과나 목표량을 작성하지 않는다.

## 10/12 추가 합의 반영

- 기존 규칙·예측 후보 중 대화로 선택한 경우에도 `source_type`은 원래 값(`prediction_personal`, `diagnosis_global` 등)을 유지한다. 대화를 거쳤다는 이유만으로 `conversation`으로 바꾸지 않는다.
- 이번 내부 서비스는 기존 후보만 고르므로 새로운 `source_type=conversation` 추천을 생성하지 않는다. 반환 `mode=conversation`은 대화 개인화 처리 상태이며 DB 출처 값과 별개다.
- 질문·답변·LLM·근거 이력은 기존 세 컬럼에 별도로 기록하고, 동일 배치 재호출 판정은 출처가 아닌 snapshot의 fingerprint를 사용한다.
- snapshot은 질문·선택지 코드, 정책/카드/모델 버전, fingerprint, 건강기록 ID를 포함한다. 자유 입력 원문·이름·연락처는 저장하지 않는다. 건강기록 ID도 개인과 연결될 수 있으므로 이 전체 저장 범위를 원본 시트에서 합의한다.
- LLM 식별자는 32자 이내다. C01~C12를 문서 순서와 무관한 고정 카드 ID로 사용하는 안을 제안하며, 수정 이력은 version으로 관리하고 삭제 ID는 재사용하지 않는다.
- 운영 승인은 12개 전체가 아니라 핵심 2~3개부터 받을 수 있다. 다른 카드는 draft로 유지하고 승인 카드만 검색에 사용한다. 좌식 카드는 기존 서버 후보에 실제 포함될 때만 연결되며 대화가 후보 제한을 우회하지 않는다.
- 외부 예측 모델의 현재 버전 확인과 모델 파일 다운로드·큐/워커 연결은 C/A 범위다. 실제 done → reco 자동 전환 확인은 워커 연결 후 통합 검사로 남긴다.

## 현재 키·목표 계약

| 코드 | 질문으로 확인할 조건 | 유지할 목표 |
| --- | --- | --- |
| CH_WALK_AFTER_MEAL | 점심·저녁 식후 모두 수행 가능. 실내 수행도 같은 두 슬롯 원형이 가능한 경우 | 회차 10분·하루 2회 |
| CH_WALK_ONE_STOP | 대중교통 이용·이동 가능 | 하루 1회 직접 확인. 이용일은 CHLG-05에서 사용자 선택 |
| CH_STAND_HOURLY | 실제 좌식 구간에서 움직임 기회 확보 | 회차 3분·하루 3회 |

이 세 키가 모든 사용자에게 추천된다는 뜻은 아니다. 먼저 기존 서버가 허용한 후보·공략 대상·점수·제외·쿨다운을 따른다.
좌식 미채택·진단자 weight 보류를 대화 답변으로 우회하지 않는다. 식후 한 슬롯만 가능하거나 5분만 가능하면 목표를 바꾸지 않는다.
활동 제한 답변은 활동 추천을 보류한다. 시작 안전 확인은 기존 CHLG-05 사용자 확인을 그대로 따른다.

공통 D28 종료, 초기 최대 2개, D7 이후 주기당 1개 추가·동시 최대 3개는 유지한다.
LLM 제안에는 난이도·시간·횟수·점수·기간·새 factor를 넣지 않으며 `proposed_goal`은 NULL이다.

## 연결 파일

- app/services/rag_cards.py: 카드 스키마·승인 필터·질문·검색·선택 검증.
- app/services/rag_provider.py: SelectionProvider, OpenAI Responses API의 엄격한 JSON 스키마 선택 어댑터.
- app/services/conversation_recommendations.py: 서버가 생성한 규칙 후보를 개인화하는 내부 연결.
- docs/01_planning/chatbot/cards-draft-20261012.json: C01~C12의 출처·연결 키·상황·승인 상태.
- docs/01_planning/chatbot/golden-cases-20261012.json: 최신 계약의 20개 평가 입력·기대 결과.
- scripts/evaluate_rag_preparation.py: 외부 호출 없이 실행하는 고정 평가.

`ConversationRecommendationService`는 기본 enabled=False다. 운영 연결에서 직접 enabled=True로 넘기기 전에 카드 승인과 API 계약을 확정한다.
인증된 서버가 `RecommendationService.generate(user)`로 만든 배치만 `personalize()`에 전달한다.
사용자 ID·모델 점수·주기·대상은 클라이언트/LLM이 정하지 않는다. `query`는 로컬 검색에만 사용하며 저장하거나 LLM에 전송하지 않는다.
선택형 답변만 개인 사용자 문맥으로 전달한다. 이름·이메일·진단 기록·원본 대화는 전송하지 않는다.

LLM이 선택한 키·근거 ID는 검색된 승인 카드와 일치해야 한다. 같은 배치를 재호출하면 첫 저장 결과를 유지한다.
모델 응답 대기 중 새 건강기록·마스터 목표·현재 대상·모델 버전·제외 상태·진행 슬롯이 바뀌면 저장을 보류한다.
후보 생성 전부터 마스터 목표가 이 버전의 고정 문답과 다르면 질문과 개인화를 보류한다.
DB 저장이 실패하면 트랜잭션 전체가 취소된다. 다른 사용자 배치 접근은 거절한다.

현재 구현의 중복 방지는 내부 후보 배치에 대한 것이다. 공개 HTTP API의 요청 식별자·재시도·세션 보관 계약까지 완성됐다고 설명하지 않는다.

## 원본 API 계약 검토안 — 아직 등록·승인되지 않음

한 번에 새 endpoint를 운영에 붙이지 않고 A/D가 다음 항목을 확정한다.

1. 대화 진입: 인증된 사용자·현재 주기의 서버 후보를 준비하고 최대 3개 선택형 질문을 반환.
2. 답변 접수: 기존 질문을 재사용하고 closed enum 답변만 받음. 질의 기록은 서버가 관리하고 클라이언트의 asked 값을 무조건 신뢰하지 않음.
3. 최종 제안: conversation / rules / ask / hold 구분, 기존 카드 필드·remaining_slots·cycle_end_date·출처·근거와 설명 반환.
4. 반복 요청: 같은 사용자·주기·현재 건강기록·모델·카드 버전·답변에 대해 같은 후보 배치를 재사용하는 요청 식별 계약.
5. 오류: 기존 오류 코드로 처리. 모델·검색 실패는 규칙 추천, 유효 규칙 후보도 없으면 보류. 새 오류 코드를 임의로 만들지 않음.
6. 시작: 기존 CHLG-05 호출. 자동 시작·공통 마스터 수정·의료 정보 덮어쓰기 없음.

기존 source_type='conversation', conversation_snapshot, llm_model_version, evidence_card_ids는 사용 가능한 상태임을 원본 시트에서 확인했다.
새 공개 API 계약은 원본 API 시트에 아직 없다. 이 문서는 그 등록을 대신하지 않는다.

## 진단자 알데 조건 제안

`D_DIAGNOSED_ALCOHOL_POLICY_ENABLED`의 기본값은 false다. 현재 음주 코드·질문 기준 기간·하루 인증 정책을 검토한 뒤 켠다.

| 입력 | weight 제안 | 의미 |
| --- | --- | --- |
| alcohol_frequency=1, alcohol_amount가 NULL/0 | 0 | 비음주 코드. 추천하지 않음 |
| alcohol_frequency=2~6 | 1 | 기존 비음주일 챌린지 적용 후보. 위험음주 등급 판정 아님 |
| 결측·비유효 코드·빈도 1인데 양 양수 | 미평가 | 추정하지 않음 |
| alcohol_amount 요인 | 기존 보류 | 이 작업에서 양별 cutoff를 승인하지 않음 |

global 중요도 × 승인된 이진 weight 경로를 그대로 사용한다. 해당 모델이 이 factor를 제공해야 하며, 공략 대상·활성 후보 조건도 유지한다.
기존 점수·XP·봉인을 수정하지 않고, 진단·복약 사용자에게 새 질환 확률을 생성하지 않는다.

코드북의 최근 1년 코드와 서비스의 최근 4주 질문이 아직 정합화되지 않았으므로 운영 활성화는 하지 않았다.
`CH_NO_DRINK_TODAY`의 하루 종료 확인은 기존 인증 정책의 검토 항목이다. 이 게이트 구현만으로 완료 시간을 새로 제한하지 않는다.

## 평가·근거·남은 작업

```bash
uv run --group app --no-sync python -m scripts.evaluate_rag_preparation
```

평가 보고서의 20개는 승인 테스트 fixture로 수행한 태그 검색·JSON 검증·D28 계약 체크다.
실제 LLM의 선택·설명 정확도, 임상 효과, 팀 운영 승인이나 검색 품질 90% 달성을 입증하지 않는다.
기존 초안의 E17~E19처럼 미확정이던 주기 사례는 현재 공통 D28·허용 키·중복 정책 기준으로 다시 작성했다.

확인한 외부 출처:
- WHO Physical activity, 2024-06-26, Overview / How much physical activity is recommended?: https://www.who.int/news-room/fact-sheets/detail/physical-activity (확인 2026-10-12).
- WHO 2020 지침 소개: https://www.who.int/publications/i/item/9789240015128 (확인 2026-10-12). 소개 페이지 확인이며 각 카드의 특정 목표 효과 근거로 사용하지 않는다.
- OpenAI Structured Outputs: https://developers.openai.com/api/docs/guides/structured-outputs (확인 2026-10-12). JSON 스키마 외에도 서버 업무 검증·거절·미완료 처리가 필요하다.

남은 연결: 카드 12개 팀 검토·운영 승인, A/D 공개 API·세션 계약, 서버 API 키·모델·비용 담당 설정,
추천 화면의 선택형 질문 연결, 실제 LLM 골든셋 실행, MySQL 경합과 전체 서비스 통합 확인.
수빈님의 원본 시트 업데이트·병주님의 큐/워커/배포와 겹치는 변경은 포함하지 않는다.

## 전달본 검증 결과

PR #46까지 반영한 main 기준 로컬 SQLite 앱 회귀 검사 343개 통과, MySQL 전용 경합 검사 2개 제외.

출처 보존 수정 후 새 기능 검사 19개·고정 평가 20개·Ruff·Mypy 143개 소스 검사를 재실행해 통과했다. 앞선 전체 343개 통과는 수정 전 전달본 결과이며 전체 회귀는 이번에 반복 실행하지 않았다.
