## 회원·인증

### REQ-USER-001 — 회원가입 · 이메일 회원가입

사용자는 이메일, 비밀번호, 닉네임을 입력하여 회원가입할 수 있다. 이메일 형식을 검증하고 중복 여부를 확인하며, 중복인 경우 409 상태코드와 '이미 가입된 이메일' 사유를 반환한다.

*기능 · 우선순위 높음*

### REQ-USER-002 — 회원가입 · 비밀번호 규칙

비밀번호는 8자 이상이며 영문과 숫자를 각각 1자 이상 포함해야 한다. 조건을 충족하지 않으면 400 상태코드와 함께 충족하지 못한 항목을 반환한다.

*기능 · 우선순위 높음*

### REQ-USER-003 — 로그인 · 이메일 로그인

사용자는 이메일과 비밀번호로 로그인하며, 성공 시 액세스 토큰과 리프레시 토큰을 발급받는다.

*기능 · 우선순위 높음*

### REQ-USER-004 — 로그인 · 로그인 실패 처리

비밀번호를 5회 연속 틀린 경우 10분간 해당 계정의 로그인을 차단하고, 응답에 남은 차단 시간을 포함한다.

*기능 · 우선순위 보통*

> 비고: 예외 상황 요구사항

### REQ-USER-005 — 로그인 · 로그아웃

사용자가 로그아웃하면 서버는 해당 리프레시 토큰을 무효화하고 인증 쿠키를 만료시킨다.

*기능 · 우선순위 높음*

### REQ-USER-006 — 회원정보 · 기본 정보 관리

사용자는 나이, 성별, 키를 등록·수정할 수 있으며, 이 값은 건강정보 입력 시 기본값으로 채워진다.

*기능 · 우선순위 높음*

### REQ-USER-007 — 회원정보 · 질환별 진단 이력 등록

사용자는 가입 시 당뇨·고혈압 각각에 대해 진단 이력과 관련 약 복용 여부를 선택한다. 진단 여부는 질환 단위로 저장하며 하나만 진단받은 경우도 구분한다. 예측 결과의 노출 범위는 REQ-PRED-007을 따른다.

*기능 · 우선순위 높음*

> 비고: 기획 문서 2.3 반영 · 9/28 질환별 기준으로 수정

### REQ-USER-008 — 회원정보 · 보상 유형 선택

사용자는 수집형·성장형·꾸미기형 중 하나의 보상 유형을 선택하며, 이후 보상 화면 구성에 사용된다. 선택하지 않은 경우 수집형을 기본값으로 한다.

*기능 · 우선순위 보통*

> 비고: users.motivation_type

### REQ-USER-009 — 회원정보 · 회원 탈퇴

사용자는 회원 탈퇴를 요청할 수 있으며, 계정은 즉시 비활성 처리되고 개인식별정보(이메일·닉네임)는 30일 후 삭제한다. 챌린지 인증으로 업로드된 사진도 같은 시점에 함께 삭제한다. 건강기록과 예측 결과는 식별정보를 제거한 뒤 통계 목적으로만 보관한다.

*기능 · 우선순위 보통*

> 비고: 개정 — 2026.09.28. 사진 인증 도입에 따라 삭제 대상에 업로드 사진 추가

### REQ-USER-010 — 고지 · 서비스 성격 고지

회원가입 시 '본 서비스는 의료 진단이 아닌 참고용'이라는 고지에 1회 동의를 받고, 동의 일시를 저장한다.

*기능 · 우선순위 높음*

> 비고: 평가항목 대비


## 건강정보

### REQ-HLTH-001 — 건강정보 입력 · 간편 모드

사용자는 나이, 성별, 키·몸무게, 허리둘레, 흡연, 음주, 걷기·근력운동, 앉아 있는 시간, 가족력, 식생활(외식 빈도) 10개 항목을 입력한다. 생활습관 문항은 원문항의 관찰 기간과 무관하게 최근 4주 기준으로 질문하고, 학습 시 원문항 척도에 맞춰 매핑한다. 최초 입력에는 소요 시간 제한을 두지 않는다.

*기능 · 우선순위 높음*

> 비고: 9개 → 10개. 식생활(L_OUT_FQ) 추가 — 소디 위협도 산출용. 문항 기간은 4주 기준 통일

### REQ-HLTH-002 — 건강정보 입력 · 정밀 모드

간편 모드 항목에 더해 수축기 혈압, 이완기 혈압, 공복혈당, 당화혈색소, 중성지방, HDL 콜레스테롤을 입력할 수 있다. 이 수치는 위험도 예측 모델의 입력으로 쓰지 않고, 혈당 캐릭터의 위협도 산출과 대사증후군 판정에만 사용한다.

*기능 · 우선순위 높음*

> 비고: 확정 — 라벨 정의에 쓰인 수치이므로 예측 입력에서 제외 (데이터 누수 방지)

### REQ-HLTH-003 — 건강정보 입력 · 입력값 검증

허용 범위를 벗어난 값은 저장하지 않고 400 상태코드와 허용 범위를 함께 반환한다. (키 100~250cm, 몸무게 30~200kg, 수축기 혈압 70~250mmHg, 공복혈당 40~500mg/dL)

*기능 · 우선순위 높음*

### REQ-HLTH-004 — 건강기록 · 시점별 저장

건강정보는 입력 시점과 함께 저장되어 동일 사용자의 기록이 시계열로 축적된다. 기존 기록을 덮어쓰지 않는다.

*기능 · 우선순위 높음*

> 비고: health_records

### REQ-HLTH-005 — 건강기록 · 기록 조회

사용자는 최근 12개월 내 본인의 건강기록을 기간 필터와 함께 조회할 수 있다.

*기능 · 우선순위 보통*

### REQ-HLTH-006 — 일일 기록 · 간편 일일 기록

일일 기록 화면은 체중·허리둘레·수축기·이완기·공복혈당을 모두 선택 입력으로 받고, 기록과 챌린지 인증은 30초 이내에 끝낼 수 있게 한다. 여기서 30초는 앱을 조작하는 시간이며 타이머가 도는 시간은 포함하지 않는다. 하나만 입력해도 저장하며 전부 비우면 저장하지 않는다. HbA1c와 지질은 검사 주기가 달라 정밀 모드에서만 받는다. 이 시간 기준은 최초 생활패턴 입력에는 적용하지 않는다.

*기능 · 우선순위 보통*

> 비고: 확정 — 30초 기준은 일일 기록·챌린지 인증에만 적용. 10/1 항목 개수 제한을 선택 입력으로 변경 (배수빈)


## 예측

### REQ-PRED-001 — 위험도 예측 · 두 질환 동시 예측

사용자는 한 번의 요청으로 당뇨와 고혈압 위험도를 함께 산출받는다. 두 질환의 입력 폼은 하나로 통합한다.

*기능 · 우선순위 높음*

### REQ-PRED-002 — 위험도 예측 · 비동기 처리

예측 요청 시 서버는 작업 ID를 즉시 반환하고, 실제 추론은 ai_worker 컨테이너에서 수행한다. 클라이언트는 작업 상태를 조회하여 완료 시 결과를 받는다.

*기능 · 우선순위 높음*

> 비고: 평가항목 3-2 / 5-5

### REQ-PRED-003 — 위험도 예측 · 결과 이력 저장

예측 결과는 입력값 스냅샷, 모델 버전, 예측 시각과 함께 저장되어 이후 추이 비교에 사용된다.

*기능 · 우선순위 높음*

> 비고: predictions

### REQ-PRED-004 — 결과 표시 · 위험도 등급 표시

위험도는 확률값과 함께 낮음·주의·높음 3단계로 표시하며, 각 구간의 경계값은 문서에 고정하여 기록한다.

*기능 · 우선순위 높음*

### REQ-PRED-005 — 결과 표시 · 위험요인 기여도

예측에 영향을 준 상위 3개 요인을 기여도 크기와 함께 제시한다. 생활습관으로 바꿀 수 있는 요인과 바꿀 수 없는 요인(나이·성별·가족력)을 구분하여 표시한다.

*기능 · 우선순위 높음*

> 비고: 평가항목 3-3

### REQ-PRED-006 — 결과 표시 · 위험도 변화 추이

직전 예측 대비 변화량을 표시하고, 최근 6회 이상의 예측 결과를 시계열 그래프로 제공한다.

*기능 · 우선순위 높음*

> 비고: 참여기업 필수 요구사항

### REQ-PRED-007 — 예외 처리 · 질환별 진단 이력 처리

진단 이력은 질환 단위로 판단한다. 진단받은 질환의 위험도 예측 결과는 노출하지 않고, 미진단 질환의 예측 결과만 노출한다. 당뇨·고혈압을 모두 진단받은 경우에만 예측 화면 전체를 감추고 기록·챌린지 기능만 제공한다. 위협도는 진단 질환은 전역 중요도 기반(global), 미진단 질환은 SHAP 기여도 기반(contribution)으로 각각 산출한 뒤 요인별로 큰 값을 채택한다.

*기능 · 우선순위 높음*

> 비고: 기획 문서 2.3 반영 · 9/28 질환별 기준으로 수정 (홍서윤·김이경 합의)

### REQ-PRED-008 — 예외 처리 · 입력 항목 부족

간편 모드 필수 항목이 누락된 상태로 예측을 요청하면 추론을 수행하지 않고 누락된 항목명을 반환한다.

*기능 · 우선순위 보통*

### REQ-PRED-009 — 결과 표시 · 최종 보스 판정

대사증후군 5개 지표(허리둘레, 혈압, 공복혈당, 중성지방, HDL) 중 3개 이상이 기준을 넘으면 최종 보스 각성 상태로 표시한다. 정밀 모드 입력이 없는 사용자에게는 판정 불가로 안내한다.

*기능 · 우선순위 2차 범위*

> 비고: 2차 범위로 이관 — 2026.09.29. 화면·API 어디에도 연결되는 지점이 없다. 판정에 필요한 혈압·혈당이 정밀 모드 선택 입력이라 미입력자는 판정 자체가 불가하고, 캐릭터 5종과 별개 로직이라 도감 편입 방식도 미정. 요구사항은 지우지 않고 남겨 둔다 (기획서 3.4 · 9.1)

### REQ-PRED-010 — 결과 표시 · 혈당 캐릭터 위협도 산출

혈당 캐릭터의 위협도는 기여도가 아니라 정밀 모드에서 입력받은 공복혈당·당화혈색소의 기준 대비 값으로 산출한다. 정밀 모드를 입력하지 않은 사용자에게는 미측정 상태로 표시한다.

*기능 · 우선순위 높음*

> 비고: 확정 — 2026.09.25. 홍서윤 확인 완료

### REQ-PRED-011 — 결과 표시 · 위협도와 공략 점수 분리

캐릭터 위협도는 건강정보를 다시 입력해 재예측할 때만 갱신한다. 누적 공략 점수를 위협도에서 직접 차감하지 않고 새 입력값으로 모델을 다시 산출한다. 공략 점수는 챌린지 수행 시 즉시 누적되는 주 단위 게임 진행값으로, 화면에서 위협도와 구분해 표시한다.

*기능 · 우선순위 높음*

> 비고: 확정 — 챌린지 수행만으로 위험도가 줄어든 것처럼 보이는 문제 방지

## 챌린지

### REQ-CHLG-001 — 챌린지 추천 · 기여요인 연계 추천

미진단자는 질환별 개인 기여요인 중 수정 가능한 factor_key에 매핑된 챌린지를 추천한다. 진단자는 해당 질환 모델의 전역 중요도와 최신 생활패턴 입력으로 factor_score를 산출한다. 두 경로 모두 동일 매핑 표를 사용하고 중복 챌린지는 합친다.

*기능 · 우선순위 높음*

> 비고: D 설계안 v3 반영 — 매핑 표 담당 김이경 (9/29)

### REQ-CHLG-002 — 챌린지 추천 · 추천·동시 진행 개수

챌린지는 한 번에 모두 제시하지 않고 주차별로 누적 투입한다. 1주차에 2개로 시작하고 2주차부터 매주 한 방향씩 추가하여 최대 3개까지 늘린다. 3주차 이후에는 추가 없이 유지한다. 동시에 진행 가능한 챌린지는 최대 3개로 제한한다. 진행 중인 챌린지가 있으면 남은 슬롯 수만큼만 추가된다.

*기능 · 우선순위 보통*

### REQ-CHLG-003 — 챌린지 수행 · 일일 다회 수행 기록

*비기능 · 우선순위 높음*
