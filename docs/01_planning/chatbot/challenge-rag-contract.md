# 챌린지 ↔ AI·RAG 연결 계약

정리: 배수빈 (D 후속 담당) · 2026-10-26 · 운영 v1.1.2 · 1단계 추천 챌린지 21개·대화형 지원 21개·승인 카드 48장 반영

AI·RAG를 붙이기 전에 챌린지 쪽이 어디까지 만들었고, AI가 어느 자리에 들어와 무엇을 바꿀 수 있는지 정리한 문서다. 공개 API 형태는 연결하는 쪽에서 정한다.

## 1. 챌린지는 지금 이렇게 돈다

1단계 기능은 모두 운영 서버에서 돌고 있다.

```
예측 완료
  → 공략 대상 자동 선정: 위협도 1위 캐릭터 하나 (도감에서 변경 가능, CHLG-10)
  → 추천 생성 CHLG-01: 규칙으로 후보 최대 3장
  → 사용자가 고름: 시작 CHLG-05 / 거절·해당 없음 CHLG-03
  → 시작하면 28일 치 예정 기회(날짜 × 슬롯)를 미리 만든다
  → 수행 기록 CHLG-07: 서버 타이머 · 직접 체크 · 사진
  → 예정 기회가 인정 완료되면: 공략 점수 +10, XP, 보상 카드 뽑기 1회
  → D28 경계에서 같은 주기 챌린지가 함께 끝난다 (이월 없음)
```

### 추천 규칙 (`app/services/recommendations.py`)

- 후보는 아래 표의 1단계 추천 대상 중 공략 대상 캐릭터의 요인에 맞는 것만 쓴다.
- 점수는 미진단 질환이면 개인 SHAP을 P95로 나눈 값, 진단 질환이면 전역 중요도 × 생활행동 가중치다. 점수 순으로 최대 3장을 낸다.
- 진행 중이거나 쿨다운·수동 제외 중인 챌린지는 빠진다. 같은 챌린지를 3번 연속 거절하면 다시 추천받을 시점(7일 · 30일 · 직접 해제)을 고른다.
- 남은 슬롯이 없으면 추천을 만들지 않는다. 시작할 때 처음 최대 2개, D7부터 주기당 1개 더, 동시에 최대 3개다.

## 2. 1단계에서 끝난 것과 안 하는 것

**끝난 것**: 위 흐름 전체(CHLG-01\~14), 도감(MNSTR-01), 보상 카드·꾸미기·성장 아이템(RWRD-01\~07), 성장 기록(PROG-01), 캐릭터 4종의 단계별 그림 5장과 변화 도감 화면. 화면은 v5로 연결했고 운영 서버에서 확인했다.

**1단계에서 안 하는 것**

- 봉인 판정. 28일이 지나면 "기간 종료"로만 보여 준다
- 실제 서비스의 캐릭터 외형 변화(REQ-RECO-008). 체험 모드에서는 수행 5회마다 한 단계씩 바뀐다. 실제 서비스는 외형을 바꿀 기준이 아직 없어 서버가 단계 값(`seal_progress`)을 비워 보내고, 도감은 1단계로 두며 변화 도감은 미리보기로 보여 준다
- 습관 형성 판정. `habit_established`가 비어 있으면 "판정 안 함"이다
- 스파이크 위협도. 실측 혈당을 위협도로 바꾸는 기준이 아직 없다
- 수치 인증(value) 챌린지, 나트륨 계열 추천, 조건이 정해지지 않은 진단자 요인(음주·체격·활동)
- **대화형 추천(REQ-CHLG-012)**. 이 문서가 넘기는 범위다

## 3. AI·RAG가 들어올 자리

### 원칙

AI는 **서버가 만든 규칙 후보 안에서 고르고 이유를 설명하는 일**만 한다. 새 챌린지, 목표량, 난이도, 점수, 기간, 요인은 만들지 않는다. 시작은 사용자가 기존 CHLG-05로 한다.

```
CHLG-01 규칙 후보 (최대 3장)
  → 부족한 정보만 선택형 질문 (최대 3개, 이미 답한 건 생략)
  → 승인된 카드 검색 (최대 3개)
  → LLM이 후보 중에서 선택 + 근거 카드 + 이유
  → 서버 검증
       통과  → conversation: 고른 카드에 이유를 붙여 보여 줌
       실패  → rules: 규칙 추천 그대로
       정보 부족 → ask: 질문을 더 함
       후보 없음 → hold: 추천 보류
  → 사용자가 CHLG-05로 시작
```

### 주고받는 값

| 방향 | 내용 |
| --- | --- |
| 서버 → LLM | 규칙 후보 배치, 선택형 답변, 검색된 승인 카드 |
| 보내지 않음 | 이름 · 이메일 · 진단 기록 · 자유 입력 원문 |
| LLM이 정하지 않음 | 사용자 · 주기 · 공략 대상 · 모델 점수. 모두 서버가 정한다 |
| LLM → 서버 | 고른 `challenge_code`, `evidence_card_ids`, `reason`(사용자에게 보여 줄 한두 문장) |
| 서버가 거절하는 응답 | 후보 배치 밖의 코드, 검색되지 않은 카드, 난이도·시간·횟수·점수를 바꾸려는 값, 질환 치료나 위험도 감소를 단정하는 문장 |

LLM 호출이 실패하거나 응답이 검증을 못 넘으면 오류를 내지 않고 `rules`로 돌아간다.

### 저장

새 테이블이나 컬럼은 만들지 않는다. `challenge_recommendations`에 이미 있는 세 칸을 쓴다.

| 컬럼 | 넣는 값 |
| --- | --- |
| `conversation_snapshot` | `policy_version` · `fingerprint` · `answers` · `asked` · `card_versions` · `model_version`(예측 모델) · `health_record_id` |
| `llm_model_version` | 선택에 쓴 LLM 식별자 (32자 이내) |
| `evidence_card_ids` | 근거로 쓴 승인 카드 ID 배열 (`C01`\~`C12`) |

- `source_type`은 원래 값(`prediction_personal` · `diagnosis_global`)을 그대로 둔다. 대화를 거쳤다고 `conversation`으로 바꾸지 않는다 (10/13 A·D 합의).
- `proposed_goal`은 NULL이다. 목표는 챌린지 마스터 값을 그대로 쓴다.
- 같은 사용자·주기·건강기록·모델·카드 버전·답변으로 다시 부르면 처음 저장한 결과를 돌려준다.

### 이미 있는 코드 (꺼진 상태)

| 파일 | 하는 일 |
| --- | --- |
| `app/services/conversation_recommendations.py` | 규칙 후보 배치를 받아 질문·검색·선택·검증·저장. 기본 `enabled=False` |
| `app/services/rag_cards.py` | 카드 스키마, 승인 카드 필터, 태그 검색, 선택 검증. 지원 코드는 1단계 추천 대상 21개 전부. 코드마다 선택형 질문 하나 |
| `app/services/rag_provider.py` | `SelectionProvider` 인터페이스와 OpenAI 어댑터. 실제 호출은 해 보지 않았다 |
| `docs/01_planning/chatbot/cards-20261026.json` | 카드 C01\~C48. 모두 승인(배수빈, 2026-10-26). 근거는 WHO 신체활동·건강한 식사·음주·흡연 팩트시트 |
| `scripts/evaluate_rag_preparation.py` | 외부 호출 없이 도는 고정 평가 54건 (`golden-cases-20261026.json`, 결과 `evaluation-20261026.json`) |

### AI가 고를 수 있는 개수

| 단계 | 개수 |
| --- | --- |
| 1단계 추천 대상 | 21개 |
| 공략 대상 캐릭터에 맞는 후보 | 비세라 13 · 알데 4 · 코티니 4 · 스파이크 0 |
| 규칙 추천 한 번에 나오는 카드 | 최대 3장 (위협도 점수 순) |
| AI가 고를 수 있는 것 | 그 3장 중 사용자가 "가능하다"고 답한 것 |

- 어느 캐릭터든 규칙이 낸 3장 안에서 AI가 고르고 이유를 붙인다. 비세라는 후보 13개, 알데·코티니는 4개 중 3장이 나온다.
- 시작할 수 있는 수는 따로 제한된다. 처음 2개, D7부터 1개 더, 동시에 최대 3개다.

### 카드를 늘리거나 고칠 때

- 근거 출처는 `https://www.who.int/` 주소만 허용한다. 페이지에 실제로 있는 문장만 근거로 쓰고, 목표량·횟수는 팀 운영 기준이라고 `policy_note`에 적는다.
- 지원 코드를 늘리면 질문(`QUESTION_TEXT`), 목표 고정 표(`FIXED_GOALS`), 승인 카드를 함께 넣어야 한다. 셋 중 하나가 빠지면 테스트가 실패한다.

공개 API, 화면, LLM 설정값(API 키·모델 이름)은 아직 없다. 임베딩이나 벡터 DB 없이 작은 카드 묶음을 태그로 검색하는 방식이다. 검색 방식은 RAG 담당이 바꿔도 되지만, 위 입출력과 검증은 지킨다.

### LLM에 더 맡겨도 되는 것

지금은 LLM이 후보 안에서 카드만 고르지만, 아래는 자동화해도 된다. 서버 검사만 지키면 된다.

| 맡겨도 되는 일 | 하려면 |
| --- | --- |
| 자유 답변을 선택지로 바꾸기 | LLM 출력이 `SituationAnswers`의 정해진 값 중 하나인지 서버가 검사한다. 애매하면 `unknown`으로 두고 다시 묻는다 |
| 질문을 대화체로 다듬기 | `QUESTION_TEXT`의 뜻은 그대로 두고 표현만 바꾼다. 답은 위처럼 선택지로 받는다 |
| 이유 문장을 사용자에 맞게 다시 쓰기 | 근거 카드 `guidance`를 바탕으로만 쓴다. 숫자·효과·질병 언급이 있으면 거절하고 카드 원문을 쓴다 |

새 챌린지 만들기, 목표량·난이도·점수 바꾸기, 위험도·위협도를 말하거나 진단처럼 말하기는 자동화하지 않는다.

## 4. 연결 전에 정한 것

카드 초안(`challenge-cards-20261002.md`) 8절에서 연결 전에 팀이 확인하자고 한 네 항목을 아래처럼 정했다.

| 항목 | 1단계 결정 |
| --- | --- |
| 사용할 키 | 1단계 추천 대상 21개 전부. 걷기·좌식만이 아니다 |
| 조정 범위 | 조정하지 않는다. 시간·횟수·슬롯은 마스터 목표 그대로 쓰고, 시작할 때 개인 목표(`proposed_goal`)가 들어오면 거절한다 |
| 근거 카드 | C01\~C48. 카드마다 WHO 출처·원문 위치·검토일이 있고, 코드별 질문과 선택 규칙에 연결돼 있다 |
| 유지 정책 | 7일 점검 화면은 없다. 계속은 그대로 진행, 조정은 하지 않고, 교체는 중단(CHLG-09)한 뒤 남은 슬롯으로 새로 시작한다. D7부터는 주기당 1개만 더 시작할 수 있다. 28일이 끝나면 다음 주기에 추천을 새로 받는다. 같은 챌린지가 다시 후보로 나올 수 있고, 지금 대화형 추천은 지난 주기 기록을 보지 않고 새 후보 안에서만 고른다 |

자동 누적, 졸업 판정, 봉인 연출은 1단계에서 하지 않는다.
