# 당고킬러 챗봇 연결용 챌린지 후보·코퍼스 매핑 초안

작성일: 2026-10-02 · 팀 검토용 v2

## 1. 이번 파일의 용도

병주님의 코퍼스 초안과 “챗봇이 사용자에게 질문하고 챌린지·난이도 설정을 돕는 방향”에 맞춰, 기존 4주 미션 목록을 생활 상황별 후보로 재정리했다.

- **고정 4주 배정표가 아니다.** 기존 주차는 추천 순서나 잠금 조건에서 제외하고, 공략 주제·상황만 보존했다.
- **운영 seed나 승인된 코퍼스가 아니다.** 연결 가능한 기존 키 후보, 신규 미션 아이디어, 확인 질문을 검토하기 위한 자료다.
- 기존 60개 선택지를 보존했다. 반복·맥락 변형이 포함되어 있으므로 60개의 독립 챌린지 키를 추가한다는 뜻은 아니다.
- 초기 범위는 병주님이 제안한 **걷기·좌식 행동**이다. 아래의 12개 카드는 상황 매핑 초안이며, 근거 검토·최신 마스터 대조 후 승인한다.
- 다른 영역의 미션도 참고 후보로 남긴다. 자료 수집 허용과 자동 추천 허용은 따로 관리한다.

## 2. 챗봇과 운영 규칙의 역할 제안

| 대상 | 역할 |
|---|---|
| 코퍼스 | 사용자 표현·제약을 해석하고 확인 질문·실천 장벽 설명의 근거를 제공 |
| 챌린지 마스터 | 사용할 수 있는 키, 목표·단위·완료 조건, 난이도별 허용값을 정의 |
| 챗봇 | 필요한 상황을 질문하고, 승인된 키·허용 난이도 안에서 후보와 이유를 제시 |
| 사용자 | 실행 가능한 미션·목표를 확인하고 시작에 동의 |
| 서버 | 키·추천 권한·허용값·동시 진행 수를 검증하고 완료·보상 규칙을 적용 |

질문과 설명은 개인화할 수 있다. 다만 기존 키가 10분으로 정의되어 있다면 챗봇이 5분으로 안내하는 것만으로 5분 완료 기준이 생기지는 않는다. 목표를 바꾸려면 해당 키의 승인된 파라미터 범위나 별도 템플릿이 먼저 필요하다. 허용값이 없으면 고정값을 사용하고, 적절한 후보가 없으면 추가 확인·선택 보류로 응답한다.

**개선 목표는 유지하면서 실천 방법을 조정하는 방향**을 제안한다. 식후 걷기가 어려우면 같은 활동 목표의 승인된 다른 방법을 찾는다. 잘하는 미션만 계속 추천하거나, 어려웠다는 이유로 미션을 자동 누적하는 정책은 이 자료에 확정하지 않는다.

동시 진행 최대 3개와 7일 단위 유지·교체·조정은 현재 대화에서 확인한 기준으로 둔다. 챗봇 방식 채택만으로 자동 누적·졸업·봉인 해제가 확정된 것으로 해석하지 않는다.

## 3. 기존 키 연결 후보

아래 식별자는 로컬 `challenge_master_v0_reviewed(2).csv`에서 확인했다. **최신 v1 승인·활성 상태를 확인한 목록은 아니다.** 미션 키와 `factor_key`는 서로 다르며, 신규 미션에 행동 요인을 임의로 연결하지 않는다.

| 영역 | 기존 미션 키 후보 | 원형·적용 시 확인할 사항 |
|---|---|---|
| 걷기 | `CH_WALK_AFTER_MEAL` | 식후 10분. 점심·저녁은 별도 신규 키가 아니라 맥락 선택. 짧은 시간 변형은 별도 승인 필요 |
| 걷기 | `CH_WALK_ONE_STOP` | 대중교통 이용 기회가 있는 경우. 걸은 시간을 검증한 것으로 취급하지 않음 |
| 좌식 행동 | `CH_STAND_HOURLY` | 3분 움직임 원형. 제목의 ‘한 시간마다’와 하루 3회 구조의 문구 정합성 검토 필요 |
| 근력 | `CH_STRENGTH_10` | 10분 원형. 운동 경험·공간·수행일·적합성 확인 후 사용 |
| 흡연 | `CH_COUNT_DOWN`, `CH_DELAY_5MIN`, `CH_NO_SMOKE_TODAY` | 현재흡연 대상. 관찰·대처 연습·하루 금연을 구분 |
| 음주 | `CH_NO_DRINK_TODAY` | 현재음주 대상. 비음주일 선택과 하루 종료 확인 정책 필요 |
| 식생활·나트륨 | `CH_HOME_MEAL`, `CH_LEAVE_SOUP`, `CH_CHECK_LABEL` | 소디 고혈압 설계와 수동 선택용 후보를 보존. 모델·위협도·자동 추천 적용은 추가 검증·팀 결정 전 후보 상태 |

계단, 오늘 외식 안 하기, 한 잔 줄이기, 술 사이 물 마시기 등 v0의 다른 카드도 있다. 이번 파일은 기존 4주 목록을 변환한 것이므로 모든 마스터 행을 다시 수록하지 않는다. 비활성·보류 미션을 챗봇 경유로 재활성화하지 않는다.

## 4. 코퍼스 카드에 붙일 항목

| 항목 | 기록 내용 |
|---|---|
| 자료 ID·상태 | 초안 / 출처 검토 / 팀 승인 / 보류. 운영 챌린지 키와 구분 |
| 영역·개선 목표 | 예: 걷기 / 생활 속 움직임 늘리기 |
| 검색 표현·태그 | 사용자의 실제 표현과 시간 부족·장소 제한 등 장벽 |
| 확인 질문 | 추천을 결정하는 데 필요한 질문만 기재 |
| 적용·제외 조건 | 필요한 생활 상황, 해당 없음, 조정·지원 경로 |
| 연결 키·대체 키 | 최신 승인 마스터에 실제 존재하는 키. 없으면 ‘신규 검토’ |
| 허용 난이도 | 단계별 시간·횟수·단위. 미정이면 숫자를 생성하지 않음 |
| 완료·기록 방식 | 실제 행동 / 관찰 / 일회성 준비. 현재 기능으로 인증 가능한지 |
| 근거 | 기관·문서명·URL·발행/갱신일·관련 내용·검토일. 해당 내용이 어떤 질문·행동을 뒷받침하는지 |
| 추천 권한 | 수동 선택 / 자동 추천 허용 / 보류를 별도 표시 |

자료 검색용 카드와 운영용 카드의 상태를 구분한다. 이 파일에는 새로 검증한 외부 근거를 추가하지 않았다. 기존 목록의 참고 자료도 카드별 관련 내용을 확인하기 전 승인 근거로 일괄 지정하지 않는다.

## 5. 첫 버전: 걷기·좌식 상황 카드 12개

아래 C01\~C12는 문서 내부 관리 번호이며 서비스 키가 아니다. **전부 근거·최신 마스터 검토 전 초안**이다. 동일 키로 연결되는 여러 사용자 상황을 담았으며, 12개의 독립 챌린지를 만들자는 뜻이 아니다.

| ID·영역 | 사용자 표현·태그 | 먼저 확인할 질문 | 연결 후보·조정 경로 |
|---|---|---|---|
| C01 걷기 | “점심 후에는 잠깐 시간 있어요.” / 식후·시간 여유 | 식후 걸을 장소와 10분 정도의 시간이 있나요? | `CH_WALK_AFTER_MEAL` 점심 맥락. 최신 적용 조건 확인 |
| C02 걷기 | “점심은 어렵고 저녁은 가능해요.” / 일정 제약 | 저녁 식후에 걷는 것이 생활 일정에 맞나요? | 동일 키의 저녁 맥락. 점심 실패를 그대로 누적하지 않음 |
| C03 걷기 | “비가 오면 밖에 못 나가요.” / 날씨·장소 제한 | 실내에서 걸을 공간이 있나요? | 실내 식후 걷기로 같은 원형을 쓸 수 있는지 검토. 5분 변형은 별도 승인 |
| C04 걷기 | “10분은 너무 길었어요.” / 난이도 부담 | 시간 자체가 문제였나요, 장소나 신체 불편 때문인가요? | 같은 목표의 승인 대안 또는 허용 단계 확인. 없으면 목표 변경 확정 보류 |
| C05 걷기 | “버스로 출퇴근해요.” / 이동 기회 | 한 정거장 먼저 내려도 일정과 이동 경로에 무리가 없나요? | `CH_WALK_ONE_STOP`. 기회·경로 확인 후 제안 |
| C06 걷기 | “차로 이동해서 한 정거장 걷기는 못 해요.” / 상황 없음 | 식후나 가까운 목적지로 이동할 때 걷는 기회가 있나요? | 식후 걷기 등 승인된 다른 후보 탐색. 가까운 목적지 걷기는 신규 검토 |
| C07 좌식 | “업무 중 계속 앉아 있어요.” / 사무직·장시간 앉기 | 중간에 일어나 잠깐 움직일 수 있나요? | `CH_STAND_HOURLY` 원형. 제목·횟수 정책 확인 |
| C08 좌식 | “자리에서 벗어나기 힘들어요.” / 장소 제한 | 자리에서 잠깐 일어날 수는 있나요, 쉬는 시간만 가능한가요? | 승인된 자리 내/휴식 시간 대안 유무 확인. 앉아서 하는 동작을 같은 완료 조건으로 임의 대체하지 않음 |
| C09 좌식 | “일에 몰입해서 잊어버려요.” / 실행 계기 부족 | 기존 쉬는 시간이나 업무 전환에 연결할 수 있나요? | 같은 미션의 실행 계기 설명 개인화. 알림 기능이 있다고 가정하지 않음 |
| C10 좌식 | “매시간은 못 하고 중간 휴식은 가능해요.” / 빈도 부담 | 언제 잠깐 움직일 기회가 있고, 몇 번이 가능한가요? | 마스터의 허용 빈도 확인. 챗봇이 기존 일일 완료·보상 횟수를 임의 변경하지 않음 |
| C11 좌식 | “오늘은 거의 서서 일했어요.” / 해당 상황 없음 | 오늘 오래 앉아 있던 구간이 있었나요? | 상황 없음으로 구분. 기회 없음 자체를 실패나 보상 성공으로 자동 판정하지 않음 |
| C12 좌식 | “지난 움직임 미션을 잘 못 했어요.” / 이전 미수행 | 못 한 이유가 기회 부족, 잊음, 부담, 불편 중 무엇에 가까운가요? | 같은 목표의 실행 계기·맥락·승인 단계 조정. 기록 누락과 실제 미수행도 구분 |

C04·C08처럼 승인 대안이 없는 경우에는 ‘챗봇이 대안을 생성했다’는 이유만으로 시작할 수 없게 한다. 대안 수집·검토와 운영 추천을 분리한다.

## 6. 기존 60개 미션 선택지 재분류

아래 표의 ‘기존 원형’은 이전 검토 파일과 v0에서 확인한 원형 재사용 후보다. 현재 운영 승인을 뜻하지 않는다. ‘신규 검토’와 ‘재사용 검토’도 검토 전 자동 추천하지 않는다.

기존 1\~4주 주제는 **추천 시 활용할 맥락**으로만 바꿨다. 특히 ‘유지·재시도’는 4주차 전용이 아니며, 사용자 경험에 따라 언제든 활용할 수 있다.

실천 체크·타이머·사진·수량 등 실제 인증 기능은 최신 마스터·API에 맞춰 연결한다. 상황 메모·주류 종류/양·거절 문장 저장 기능이 이미 있다고 가정하지 않는다. 스파이크·비세라가 공유하는 식후 걷기는 동일 미션·수행 기록의 재사용과 중복 보상 방지를 검토한다.

챌린지 수행·XP·공략 연출과 건강 위협도·모델 입력을 구분한다. 준비·관찰·타이머 완료로 건강 효과를 확정하거나 입력값을 자동 변경하지 않는다. 흡연·음주 미션은 해당 사용자만 대상으로 하고, 활동 미션의 적합성 확인은 기존 안전 정책에 따른다.
